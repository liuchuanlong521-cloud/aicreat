::: tip 核心考点
前言

如果你在使用大模型 API 时仔细看过账单，你会发现收费单位不是"字"，也不是"词"，而是一个看起来陌生的词——**Token**。

"这段文字有多少 Token？""上下文超长了，Token 数超了。""这个模型支持 128K Token 的上下文。"

Token 是大模型世界的基础货币。理解 Token，就是理解大模型的"计量单位"——它决定了你的成本、决定了模型能处理多长的文本、甚至影响模型的理解和生成质量。

本文将用大量例子和类比，帮你彻底搞懂 Token 是什么、怎么计算的、以及作为 AI PM，你需要关注哪些 Token 相关的问题。
:::

##  一、Token 是什么？大模型的"文字积木"

###  （一）一个形象的类比：乐高积木

想象你要用乐高积木拼一座城堡。

**人类的文字就像"完整的积木块"**：

> 一个词就是一个整体。"苹果"是一个词，"好吃"是一个词，"人工智能"是一个词。你数一下，这句话有 3 个词。

**大模型的 Token 就像"碎裂的积木片"**：

> 大模型不直接处理"词"，而是处理更小的片段——Token。
> 
> -   "苹果"可能是一个 Token
> -   "好吃"可能被拆成"好"+"吃"两个 Token
> -   "人工智能"可能被拆成"人工"+"智能"两个 Token
> -   英文单词 "unbelievable" 可能被拆成 "un"+"believ"+"able" 三个 Token

**为什么大模型要用 Token 而不是直接用词？**

> 因为世界上的语言太多了——中文、英文、日文、阿拉伯文、编程代码、数学公式……如果每个词都对应一个独立的编号，那词汇表会大到无法想象。
> 
> Tokenization（分词）就是把这些五花八门的文字，统一切成大模型能处理的小片段。每个 Token 对应一个数字编号，大模型本质上处理的是这些数字。

###  （二）Token 的技术定义

**Token 是文本被拆分后的最小单位**，是模型处理文本的基本单元。

```
原始文本："今天天气很好"
    ↓
分词器（Tokenizer）处理
    ↓
Token 序列：[今天] [天气] [很] [好]
    ↓
转换成数字编号：[5234] [8912] [102] [45]
    ↓
大模型处理这些数字
```

**关键理解**：

> 大模型看到的不是"今天天气很好"这六个汉字，而是 \[5234, 8912, 102, 45\] 这四个数字。
> 
> 同样，大模型生成时也是先生成数字，再把这些数字转换回 Token，最后拼接成你能看懂的文字。

##  二、Token 是怎么切出来的？分词方法演进

###  （一）空格分词：最简单也最粗糙

英文可以用空格分词：

```
"I love artificial intelligence"
→ [I] [love] [artificial] [intelligence]（4 个 Token）
```

**问题**：

-   中文没有空格，无法使用
-   词汇表太大（英文有几十万个单词）
-   没见过的新词无法处理

###  （二）字符分词： vocabulary 最小，但序列太长

把每个字符/字母作为一个 Token：

```
"人工智能"
→ [人] [工] [智] [能]（4 个 Token）

"unbelievable"
→ [u] [n] [b] [e] [l] [i] [e] [v] [a] [b] [l] [e]（12 个 Token）
```

**问题**：

-   序列太长，计算成本高
-   模型需要学会 "u-n-b-e-l-i-e-v-a-b-l-e" 组合起来才是 "unbelievable"
-   中文常用字只有几千个，但每个字单独学语义效率低

###  （三）子词分词（Subword Tokenization）：当前主流

**核心思想**：在"词"和"字符"之间找到平衡——常用词保持完整，生僻词拆成子词。

<table><thead><tr><th style="text-align:left;">分词方法</th><th style="text-align:left;">代表</th><th style="text-align:left;">特点</th></tr></thead><tbody><tr><td style="text-align:left;"><strong>BPE</strong></td><td style="text-align:left;">GPT-2、RoBERTa</td><td style="text-align:left;">合并频率最高的字符对，逐步构建词汇表</td></tr><tr><td style="text-align:left;"><strong>WordPiece</strong></td><td style="text-align:left;">BERT</td><td style="text-align:left;">基于概率，选择最能提升语言模型概率的合并</td></tr><tr><td style="text-align:left;"><strong>SentencePiece</strong></td><td style="text-align:left;">T5、LLaMA、Qwen</td><td style="text-align:left;">不依赖空格，把文本当纯字符流处理，适合多语言</td></tr><tr><td style="text-align:left;"><strong>Unigram</strong></td><td style="text-align:left;">AlBERT、XLNet</td><td style="text-align:left;">从大的词汇表开始，逐步删减</td></tr></tbody></table>

**BPE 的直觉**：

> 想象你在整理一个图书馆：
> 
> -   一开始，每个字母是一本书（a, b, c...）
> -   你发现 "th" 这对字母经常一起出现，就把它们合并成一本书
> -   然后 "the" 也经常一起出现，再合并
> -   最终，常用词保持完整（"the" "and" "is"），罕见词被拆成子词（"unbelievable" → "un"+"believ"+"able"）

**SentencePiece 的优势**：

> 大多数分词方法假设英文有空格、中文没空格。SentencePiece 说："我不管你的语言有没有空格，我把所有文字都当成一串字符，用统一的方式切。"
> 
> 这让它特别适合多语言模型——同一个分词器可以处理中文、英文、日文、代码，不需要为每种语言单独设计规则。

##  三、不同语言的 Token 数量差异

这是 AI PM 必须知道的——**同样的意思，用不同语言表达，Token 数可能差几倍**。

###  （一）中英文 Token 对比

<table><thead><tr><th style="text-align:left;">中文</th><th style="text-align:left;">英文</th><th style="text-align:left;">中文 Token 数</th><th style="text-align:left;">英文 Token 数</th></tr></thead><tbody><tr><td style="text-align:left;">你好</td><td style="text-align:left;">Hello</td><td style="text-align:left;">2</td><td style="text-align:left;">1</td></tr><tr><td style="text-align:left;">今天天气很好</td><td style="text-align:left;">The weather is nice today</td><td style="text-align:left;">5</td><td style="text-align:left;">5</td></tr><tr><td style="text-align:left;">人工智能正在改变世界</td><td style="text-align:left;">Artificial intelligence is changing the world</td><td style="text-align:left;">9</td><td style="text-align:left;">7</td></tr><tr><td style="text-align:left;">我最喜欢的食物是寿司</td><td style="text-align:left;">My favorite food is sushi</td><td style="text-align:left;">9</td><td style="text-align:left;">6</td></tr><tr><td style="text-align:left;">中华人民共和国</td><td style="text-align:left;">People's Republic of China</td><td style="text-align:left;">4</td><td style="text-align:left;">6</td></tr></tbody></table>

**规律**：

> -   中文通常 **1-2 个汉字 = 1 个 Token**
> -   英文通常 **1 个单词 ≈ 1-1.5 个 Token**（简单词 1 个，复杂词 2-3 个）
> -   整体而言，**同样的内容，中文的 Token 数通常比英文多 20%-50%**

**这意味着**：

> 如果你同时做中文和英文产品，**中文用户的成本更高**——同样的服务，中文消耗的 Token 更多，账单更贵。

###  （二）编程语言的 Token 特点

```
# Python 代码
def hello_world():
    print("Hello, World!")
# Token 数：约 15-20 个
```

```
// JavaScript 代码
function helloWorld() {
    console.log("Hello, World!");
}
// Token 数：约 15-20 个
```

> 代码中的缩进、换行、括号都会被算成 Token。所以代码通常比自然语言更"费 Token"。

##  四、上下文长度：模型能"记住"多少 Token

###  （一）上下文长度的演进

上下文长度（Context Length）决定了模型一次能处理多长的文本。

<table><thead><tr><th style="text-align:left;">模型</th><th style="text-align:left;">上下文长度</th><th style="text-align:left;">相当于</th></tr></thead><tbody><tr><td style="text-align:left;">GPT-3</td><td style="text-align:left;">2048 Token</td><td style="text-align:left;">约 1500 个汉字</td></tr><tr><td style="text-align:left;">GPT-3.5</td><td style="text-align:left;">4096 Token</td><td style="text-align:left;">约 3000 个汉字</td></tr><tr><td style="text-align:left;">GPT-4</td><td style="text-align:left;">128K Token</td><td style="text-align:left;">约 10 万字</td></tr><tr><td style="text-align:left;">Claude 3</td><td style="text-align:left;">200K Token</td><td style="text-align:left;">约 15 万字</td></tr><tr><td style="text-align:left;">Kimi</td><td style="text-align:left;">200K Token</td><td style="text-align:left;">约 15 万字</td></tr><tr><td style="text-align:left;">Gemini 1.5</td><td style="text-align:left;">1M Token</td><td style="text-align:left;">约 75 万字（一本书）</td></tr></tbody></table>

**上下文长度的产品意义**：

> -   4K：能处理一篇短文、几轮对话
> -   32K：能处理一篇长论文、一份合同
> -   128K：能处理一部长篇小说、一个大型代码库
> -   1M：能处理整本书、整个项目的代码

###  （二）上下文长度的实际限制

**注意**：模型"支持"某个上下文长度，不代表在这个长度上效果一样好。

**AI PM 关注点**：

> 即使模型支持 128K 上下文，也不要把 128K 都塞满。实际使用中：
> 
> -   **关键信息放在开头或结尾**——中间最容易被遗忘
> -   **能精简就精简**——每多一个 Token 都是成本
> -   **超长文档考虑 RAG**——不要指望模型记住整本书

##  五、Token 与成本：你的每一分钱花在哪了

###  （一）API 计费方式

大模型 API 的计费通常是：

```
总费用 = 输入 Token 数 × 输入单价 + 输出 Token 数 × 输出单价
```

**为什么输出比输入贵？**

> 因为生成输出时，模型需要逐个 Token 自回归生成，计算量更大。

###  （三）成本计算实例

**场景 1：智能客服**

> 每次对话平均：
> 
> -   系统 Prompt：500 Token
> -   用户输入：100 Token
> -   历史对话（10 轮）：2000 Token
> -   模型输出：300 Token
> -   总计输入：2600 Token，输出：300 Token
> 
> 用 GPT-3.5 Turbo：
> 
> -   单次成本 = 2.6 × $0.0005 + 0.3 × $0.0015 = $0.00175
> -   日活 1 万用户，每人 5 次对话：1 万 × 5 × $0.00175 = **$87.5/天**

**场景 2：长文档分析**

> 上传一份 50 页的法律合同：
> 
> -   文档内容：约 15000 Token
> -   分析指令：200 Token
> -   模型输出：2000 Token
> 
> 用 GPT-4：
> 
> -   单次成本 = 15.2 × $0.03 + 2 × $0.06 = $0.576
> -   每天分析 100 份合同：100 × $0.576 = **$57.6/天**

##  六、Token 对模型理解的影响

###  （一）分词方式影响理解

不同的分词方式，会导致模型对同一个词的理解不同。

**例子**："苹果"

<table><thead><tr><th style="text-align:left;">分词结果</th><th style="text-align:left;">模型理解</th></tr></thead><tbody><tr><td style="text-align:left;">[苹果]</td><td style="text-align:left;">一个完整的概念（水果或公司）</td></tr><tr><td style="text-align:left;">[苹] [果]</td><td style="text-align:left;">模型需要额外学习"苹"+"果"=水果</td></tr></tbody></table>

**例子**："Transformer"

<table><thead><tr><th style="text-align:left;">分词结果</th><th style="text-align:left;">模型理解</th></tr></thead><tbody><tr><td style="text-align:left;">[Transformer]</td><td style="text-align:left;">一个完整的概念（注意力架构）</td></tr><tr><td style="text-align:left;">[Trans] [former]</td><td style="text-align:left;">模型可能误解为"运输者"+"前"</td></tr></tbody></table>

**这对产品的启示**：

> -   如果你的领域有大量专有名词，确保这些名词在分词时不要被错误拆分
> -   可以在 Prompt 中明确定义术语，帮助模型正确理解

###  （二）Token 边界问题

模型是按 Token 预测的，不是按字或词预测的。这会导致一些有趣的现象：

**案例 1：密码/验证码**

> 如果你让模型生成一个 6 位验证码："请生成一个验证码：\_\_\_\_\_\_"
> 
> 模型是按 Token 生成的，它可能生成 "A3F" 作为一个 Token，"9K" 作为另一个 Token——结果不是一个字符一个字符生成的。
> 
> **解决方案**：明确要求"每个字符之间用空格分隔"，或者后处理。

**案例 2：中文数字**

> "一千二百三十四"可能被分成 \[一千\] \[二百\] \[三\] \[十四\]，而不是 \[一\] \[千\] \[二\] \[百\] \[三\] \[十\] \[四\]。
> 
> 这在需要精确数字计算的场景可能出问题。

###  （二）代码中计算 Token

```
import tiktoken

# 获取 GPT-4 的分词器
encoder = tiktoken.encoding_for_model("gpt-4")

# 计算 Token 数
text = "今天天气很好，适合出去散步。"
tokens = encoder.encode(text)
print(f"Token 数: {len(tokens)}")  # 输出: Token 数: 11
print(f"Token 列表: {tokens}")    # 输出数字编号
```

##  九、小结

###  核心要点

1.  **Token 是大模型的"文字积木"**：文本被分词器切分成 Token，模型实际处理的是 Token 对应的数字编号。
    
2.  **不同语言 Token 效率不同**：中文通常 1-2 字 = 1 Token，英文 1 词 ≈ 1-1.5 Token。同样的内容，中文消耗更多 Token，成本更高。
    
3.  **上下文长度是硬限制**：模型一次能处理的 Token 数有限，关键信息放在开头或结尾，中间最容易被遗忘。
    
4.  **Token 就是钱**：API 按 Token 计费，优化 Token 使用就是优化成本。精简 Prompt、压缩历史、模型路由是三大降本手段。
    
5.  **分词方式影响理解**：专有名词被错误拆分会影响模型理解，Prompt 中可以明确定义术语。
    

###  给 AI PM 的一句话

> **Token 是大模型世界的"货币"和"度量衡"。理解 Token，你就能理解为什么长文档处理那么贵、为什么中文比英文成本高、为什么你的 Prompt 要精简。在和算法团队讨论方案时，用 Token 数来说话，比用"字"或"词"更专业、更精准。**
