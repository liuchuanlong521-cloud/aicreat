**关键决策点**：

```
任务类型判断
    │
    ├─ 文本理解（分类/抽取/匹配）→ Encoder-only（BERT 类）或 Prompt
    │
    ├─ 文本生成（写作/对话/翻译）→ Decoder-only（GPT 类）
    │
    ├─ 需要实时知识 → RAG
    │
    ├─ 需要特定风格/格式 → 微调（LoRA）
    │
    └─ 需要执行操作 → Agent + Function Calling
```

**PM 决策要点**：这一层决定"做什么"，需要平衡用户体验、业务价值和实现成本。

####  第 2 层：Agent 编排层

Agent 是 2024-2025 年最核心的技术方向，PM 必须理解 Agent 的编排逻辑。

**Agent 核心能力**：

-   **自主规划（Planning）**：Agent 如何分解任务、制定执行计划
-   **记忆能力（Memory）**：短期记忆（对话上下文）vs 长期记忆（知识库）
-   **工具使用（Tool Use）**：调用外部 API、数据库、搜索引擎
-   **反思学习（Reflection）**：自我纠错、结果评估、策略优化

**编排与协作**：

-   **Multi-Agent 协作**：多个 Agent 分工配合（如一个负责规划、一个负责执行）
-   **Workflow 编排**：固定流程的 AI 工作流（适合确定性高的场景）
-   **任务分解与调度**：复杂任务如何拆分为子任务并分配给不同 Agent
-   **状态管理与监控**：Agent 执行过程的状态追踪和异常处理

**主流框架与协议**：

-   **LangGraph**：基于 LangChain 的图结构 Agent 编排
-   **CrewAI**：多 Agent 协作框架
-   **AutoGen**：微软开源的多 Agent 对话框架
-   **A2A / A1 / SKILL**：新兴的 Agent 间通信协议

**PM 决策要点**：选择 Workflow 还是 Multi-Agent？简单场景用 Workflow（可控、成本低），复杂开放场景用 Multi-Agent（灵活、上限高）。

####  第 3 层：大模型能力层

这是 AI 系统的"大脑"，PM 需要了解主流模型的能力边界。

**主流大模型**：

-   **GPT-4o / GPT-4**：综合能力最强，适合复杂推理、多模态场景
-   **Claude 3**：长上下文（200K）、代码能力强、安全性高
-   **Gemini**：Google 生态集成、多模态原生
-   **通义千问（Qwen）**：中文能力强、开源生态丰富
-   **DeepSeek**：推理能力强、性价比高、开源可私有化

**模型能力维度**：

-   **理解与生成**：文本理解、内容创作、代码生成
-   **Function Call（函数调用）**：结构化调用外部工具的能力
-   **Tool Use（工具使用）**：更广泛的工具调用能力
-   **推理能力**：逻辑推理、数学计算、因果分析
-   **多模态能力**：文本、图像、音频、视频的理解与生成
-   **长上下文处理**：处理超长文档（100K+ Token）的能力

**PM 决策要点**：模型选型不是"选最好的"，而是"选最合适的"。要考虑：语言能力、上下文长度、多模态需求、成本、延迟、私有化要求。

####  第 4 层：知识增强层（RAG）

RAG 是企业落地 AI 的"标配"，让大模型拥有企业私有知识。

**RAG 完整流程**：

```
数据接入 → 文本分块（Chunking）→ Embedding 向量化 → 向量检索（Retrieval）→ 重排序（Rerank）→ 增强生成（Generation）
```

**关键技术组件**：

**PM 决策要点**：RAG 的效果 80% 取决于数据质量和检索策略，而不是模型。PM 要重点关注：文档切分策略、检索准确率、幻觉控制。

####  第 5 层：模型工程层

这是算法团队的"主场"，但 PM 需要理解原理以便评估项目可行性。

**模型优化方向**：

-   **Prompt Engineering**：零成本优化，PM 的核心技能
-   **Context Engineering**：上下文工程，优化输入结构
-   **Tokenization**：分词策略影响成本和效果
-   **Quantization（量化）**：降低模型精度以减少资源占用

**模型微调与对齐**：

-   **Fine-tuning（全量微调）**：数据量充足时的方案
-   **LoRA / QLoRA**：低秩适配，参数高效微调，主流方案
-   **PEFT**：参数高效微调技术集合
-   **RLHF / DPO**：人类反馈强化学习 / 直接偏好优化，对齐人类价值观
-   **Alignment（模型对齐）**：安全、价值观、业务目标的一致性

**PM 决策要点**：Prompt → RAG → 微调，这个优先级顺序在 90% 的场景下成立。不要轻易选择微调，成本高、周期长、维护难。

####  第 6 层：工具连接层

AI 系统不是孤立的，必须连接企业现有系统。

**连接协议与方式**：

-   **MCP（Model Context Protocol）**：Anthropic 推出的标准协议，让模型安全地连接外部工具和数据源
-   **API / SDK 调用**：直接调用第三方服务
-   **Function Call（函数调用）**：模型原生支持的调用方式
-   **Webhooks（事件订阅）**：异步事件通知机制

**企业系统与工具**：

-   **ERP / CRM / OA / SAP**：企业核心系统
-   **数据库**：结构化数据的来源
-   **第三方 API**：地图、支付、短信等外部能力

**PM 决策要点**：MCP 是 2025 年的重要趋势，它统一了模型与工具的连接标准。PM 要推动技术团队关注 MCP 生态，降低集成成本。

####  第 7 层：数据基础设施层

数据是 AI 的燃料，PM 需要了解数据层的架构。

**结构化数据**：

-   **MySQL / PostgreSQL / SQL Server / Oracle**：关系型数据库

**非结构化数据与搜索**：

-   **Redis**：缓存、会话存储、向量存储（Redis Stack）
-   **Elasticsearch**：全文检索、日志分析
-   **MongoDB**：文档数据库
-   **Neo4j**：图数据库，知识图谱存储

**向量与搜索引擎**：

-   **Milvus / Pinecone / Weaviate / Qdrant**：专业向量数据库

**PM 决策要点**：数据层的选择直接影响 RAG 效果和系统性能。PM 需要和数据团队一起评估：数据量、查询模式、延迟要求、成本预算。

####  第 8 层：云原生基础层

这是运维和基础设施团队负责的层，PM 需要了解基本概念以便评估资源需求。

**基础设施**：

-   **Docker / Kubernetes**：容器化与编排
-   **GPU 集群（NVIDIA）**：模型训练和推理的算力基础
-   **存储（OSS / CDN）**：对象存储、内容分发
-   **网络（VPC / CDN）**：虚拟私有云、加速网络

**DevOps & 运维**：

-   **CI / CD**：持续集成与持续部署
-   **监控告警（Prometheus）**：系统监控
-   **日志管理（ELK）**：日志收集与分析
-   **链路追踪（Tracing）**：请求链路追踪
-   **备份恢复（Backup）**：数据备份策略

**安全与合规**：

-   **身份认证（IAM）**：统一身份管理
-   **数据安全（加密/脱敏）**：数据保护
-   **权限管理（RBAC）**：基于角色的访问控制
-   **审计日志（Logs）**：操作审计
-   **合规管理（Compliance）**：满足行业合规要求

**PM 决策要点**：云原生层的决策主要影响：部署成本、运维复杂度、扩展能力、安全合规。私有化部署 vs 公有云，这是 PM 必须参与的战略决策。

```
    │
    ├─ 预算约束：月预算 1 万还是 100 万？
    │   ├─ 1 万 → 开源模型 + 私有化
    │   └─ 100 万 → GPT-4 + 全链路优化
    │
    ├─ 延迟要求：必须 < 1 秒还是可以等 5 秒？
    │   ├─ < 1 秒 → 小模型或流式输出
    │   └─ 5 秒 → 大模型没问题
    │
    ├─ 数据隐私：能否上传第三方？
    │   ├─ 不能 → 必须私有化部署
    │   └─ 能 → API 方案更经济
    │
    └─ 维护能力：有没有算法团队？
        ├─ 没有 → 优先用 SaaS/PaaS 方案
        └─ 有 → 可以考虑开源方案
```

##  八、小结

###  核心要点

1.  **AI PM 的技术知识是金字塔结构**：基础概念 → 模型原理 → 工程化能力 → 商业判断 → 横向支撑能力。
    
2.  **第三层（工程化）是 PM 的核心竞争力**：Prompt Engineering、RAG、Agent 的设计能力，直接决定产品体验。
    
3.  **第四层（商业判断）是 PM 的终极价值**：技术方案的选择、成本的控制、风险的评估，这些决策直接影响产品的成败。
    
4.  **第五层（横向能力）是高阶 AI PM 的分水岭**：安全合规、数据治理、模型治理、成本治理，这些能力决定你能否驾驭企业级项目。
    
5.  **企业级 AI 项目是端到端的系统工程**：从需求规划到运营优化，7 个阶段环环相扣，PM 必须理解全流程。
    
6.  **8 层技术栈是 AI PM 的"地图"**：业务应用 → Agent 编排 → 大模型 → RAG → 模型工程 → 工具连接 → 数据基础设施 → 云原生基础。看懂地图，才能选对路线。
    
7.  **不要成为"技术恐惧型"PM**：你不需要推导公式、不需要写代码，但你需要理解原理、能力边界和成本结构。
    
8.  **也不要成为"技术沉迷型"PM**：技术是为了产品服务的，钻得太深会偏离产品本质。
    
9.  **持续学习是必修课**：AI 技术迭代极快，3 个月前的"前沿"可能已经是"标配"。保持好奇心、持续实践、多和工程师交流。
    

###  给 AI PM 的一句话

> **技术知识是 AI PM 的"语言"——它让你能和算法团队坐在同一张桌子上对话，而不是只能点头说"嗯，挺厉害的"。但记住：技术只是手段，产品才是目的。最好的 AI PM，不是最懂技术的人，而是最懂"如何用技术解决用户问题"的人。当你能画出 8 层技术栈、梳理端到端流程、把控横向治理能力时，你就从"功能型 PM"进化成了"架构型 PM"。**
