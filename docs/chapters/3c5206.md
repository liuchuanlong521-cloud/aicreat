::: tip 核心考点
前言

ChatGPT 能回答问题、写文章、写代码——但它不能帮你订机票、不能帮你发邮件、不能帮你操作 Excel。为什么？因为大模型本质上是一个"只动口不动手"的"大脑"，它没有"手"和"脚"去和真实世界交互。

**Agent（智能体）** 就是给大模型装上"手"和"脚"——让它不仅能思考，还能行动。它能查天气、能调用 API、能操作软件、甚至能自动完成一个复杂的项目。

2024-2025 年，Agent 被认为是大模型应用的下一个主战场。本文将系统讲解 Agent 的核心概念、架构设计、关键技术和产品实践。
:::

##  一、什么是 Agent？从"问答"到"执行"

###  （一）一个形象的类比：从"顾问"到"助理"

**大模型（无 Agent）像一位"口头顾问"**：

> 你问他"明天北京天气怎么样？" 他说："根据历史数据，北京明天可能是晴天，气温 15-25℃。但我无法获取实时数据，建议您查看天气预报。"
> 
> 他告诉你"该怎么做"，但他自己不做。

**Agent 像一位"执行助理"**：

> 你跟他说"帮我查一下明天北京的天气，如果下雨就提醒我带伞，顺便把下周去北京的机票订了。"
> 
> 他：
> 
> 1.  调用天气 API，查到明天北京有小雨
> 2.  在你的日历上添加提醒"带伞"
> 3.  打开订票网站，搜索下周去北京的航班
> 4.  把可选航班列表发给你确认
> 
> 他不仅"回答"，还"执行"。

###  （二）Agent 的核心定义

Agent 是一个能够**感知环境、做出决策、执行行动**的自主系统。在大模型时代，Agent 的核心是：

```
大模型（大脑：推理、规划、决策）
    +
工具（手脚：调用 API、操作软件、查询数据库）
    +
记忆（经验：记住之前的对话和结果）
    =
Agent（能思考、能行动、能学习的智能体）
```

##  二、Agent 的架构设计

###  （一）基础架构：ReAct 模式

ReAct（Reasoning + Acting）是当前最流行的 Agent 架构模式。

![](https://oss.fullcoding.cn/20260525/e0c097f7-5b26-40aa-adc0-3908692aab2c_1779697724144.png)

**核心循环**：

```
观察（Observation）→ 思考（Thought）→ 行动（Action）→ 观察（Observation）→ ...
```

**示例**：

```
用户："北京明天天气怎么样？适合穿什么？"

【Step 1】思考：用户想知道北京明天的天气和穿衣建议。我需要先查天气。
【Step 1】行动：调用 get_weather(city="北京", date="明天")
【Step 1】观察：{ "weather": "小雨", "temperature": "12-18℃", "wind": "北风 3 级" }

【Step 2】思考：明天有小雨，气温 12-18℃，有风。建议带伞，穿外套。
【Step 2】行动：调用 get_clothing_advice(weather="小雨", temp="12-18℃")
【Step 2】观察：{ "advice": "建议穿风衣或薄外套，带雨伞，穿防滑鞋" }

【Step 3】思考：我已经获得了所有需要的信息，可以生成回答了。
【Step 3】最终回答："北京明天有小雨，气温 12-18℃，北风 3 级。建议穿风衣或薄外套，记得带伞，最好穿防滑鞋。"
```

###  （二）进阶架构：规划-执行-反思

更复杂的 Agent 采用三层架构：

![](https://oss.fullcoding.cn/20260601/ScreenShot_2026-06-01_113207_337_1780284977467.png)

**示例：自动写一份行业分析报告**

```
【规划层】
任务：写一份关于"新能源汽车行业 2024"的分析报告
计划：
1. 搜索最新的行业数据和市场规模
2. 搜索主要厂商的销量和排名
3. 搜索政策动态和技术趋势
4. 整合信息，撰写报告大纲
5. 填充各部分内容
6. 检查报告完整性和准确性

【执行层】
- 调用搜索工具获取数据
- 调用数据分析工具整理表格
- 调用大模型生成文字内容

【反思层】
- 检查：数据是否最新？来源是否可靠？
- 发现：某条数据来自 2022 年，太旧了
- 重新规划：重新搜索 2024 年的最新数据
```

##  三、Agent 的关键技术组件

###  （一）Function Calling：让模型"调用工具"

Function Calling（函数调用）是大模型使用工具的核心机制。

**工作原理**：

```
用户："北京明天天气怎么样？"

模型分析：需要查询天气 → 需要调用 get_weather 函数
    ↓
模型输出函数调用请求：
{
  "function": "get_weather",
  "arguments": {
    "city": "北京",
    "date": "明天"
  }
}
    ↓
系统执行函数，返回结果：
{ "weather": "小雨", "temperature": "12-18℃" }
    ↓
模型基于结果生成回答："北京明天有小雨..."
```

**Function 定义示例**：

```
{
  "name": "get_weather",
  "description": "查询指定城市的天气信息",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "城市名称，如'北京'、'上海'"
      },
      "date": {
        "type": "string",
        "description": "日期，如'今天'、'明天'、'2024-05-01'"
      }
    },
    "required": ["city", "date"]
  }
}
```

**支持的模型**：

###  （四）反思机制：自我纠错

**核心思想**：让 Agent 检查自己的输出，发现错误后修正。

**示例**：

```
Agent 生成了一段代码
    ↓
反思：这段代码有没有语法错误？逻辑是否正确？边界情况处理了没？
    ↓
发现：忘记处理空输入的情况
    ↓
修正：添加空输入检查
    ↓
再次反思：还有没有其他问题？
    ↓
确认无误 → 输出最终代码
```

##  五、Agent 的产品设计原则

###  （一）从"全自动"到"半自动"

**当前 Agent 的局限**：

-   规划能力不稳定，复杂任务容易"走错路"
-   工具调用可能出错，需要兜底
-   安全性风险（让 AI 自动操作账户？）

**推荐的产品策略**：

```
阶段 1：辅助模式（Copilot）
    └── Agent 生成建议，人类确认后执行
    └── 例如：Agent 生成邮件草稿，用户编辑后发送

阶段 2：半自动模式（Human-in-the-loop）
    └── Agent 自动执行，关键步骤需要人类确认
    └── 例如：Agent 搜索机票，生成订单，用户确认后支付

阶段 3：全自动模式（Autonomous）
    └── Agent 完全自主执行
    └── 仅在异常时通知人类
    └── 适合低风险、高重复性任务
```

###  （二）Agent 的可观测性

Agent 的"黑箱"特性比大模型更严重——它可能执行了一系列操作，你不知道它为什么这么做。

**必须提供的可观测性**：

##  六、Agent 的典型应用场景

###  （一）个人助理

**场景**：管理日程、回复邮件、查询信息、预订服务。

**示例**：

> "下周三我要和客户开会，帮我：
> 
> 1.  查看我的日历，找个合适的时间
> 2.  查一下客户的背景信息
> 3.  预订一个安静的会议室
> 4.  发邮件邀请客户
> 5.  准备一份会议议程"

###  （二）智能客服（从问答到执行）

**场景**：不仅能回答问题，还能帮用户操作。

**示例**：

> 用户："我想退掉昨天买的那个耳机"
> 
> Agent：
> 
> 1.  查询用户订单 → 找到耳机订单
> 2.  确认是否符合退货条件 → 符合
> 3.  生成退货单 → 提交
> 4.  通知用户 → "退货申请已提交，快递将在明天上门取件"

###  （三）数据分析助手

**场景**：自动获取数据、分析、生成报告。

**示例**：

> "分析一下我们 Q3 的销售额，和 Q2 对比，找出增长最快的产品线，生成一份 PPT"
> 
> Agent：
> 
> 1.  连接数据库，查询 Q2/Q3 销售数据
> 2.  计算同比增长率
> 3.  排序找出增长最快的产品线
> 4.  生成可视化图表
> 5.  撰写分析报告
> 6.  生成 PPT

###  （四）代码助手（Devin、GitHub Copilot Workspace）

**场景**：从需求到代码到部署的全流程。

**示例**：

> "给网站加一个用户登录功能，用 JWT 认证"
> 
> Agent：
> 
> 1.  分析需求 → 确定技术方案
> 2.  创建数据库表
> 3.  写后端 API（登录、注册、鉴权）
> 4.  写前端页面
> 5.  写单元测试
> 6.  运行测试 → 发现问题 → 修复
> 7.  提交代码

##  九、小结

###  核心要点

1.  **Agent = 大模型 + 工具 + 记忆 + 规划**：让 AI 从"只动口"变成"既能说也能做"。
    
2.  **ReAct 是主流架构**：观察→思考→行动→观察的循环。
    
3.  **Function Calling 是工具使用的核心机制**：模型输出函数调用请求，系统执行后返回结果。
    
4.  **从 Copilot 到 Autonomous 是产品演进路径**：不要一上来就做全自动，先从辅助模式开始。
    
5.  **可观测性和安全性是 Agent 产品的底线**：用户需要知道 Agent 在做什么，以及为什么这么做。
    
6.  **当前 Agent 仍处于早期**：单工具调用成熟，多工具组合和长程规划仍有挑战。
    

###  给 AI PM 的一句话

> **Agent 是大模型从"玩具"走向"工具"的关键一步。作为 PM，你的核心任务不是设计 Agent 的算法，而是设计 Agent 的"行为边界"——它能做什么、不能做什么、什么时候需要人类确认、出错时怎么兜底。Agent 产品的成功，80% 取决于工程设计和安全管控，20% 取决于模型能力。**
