##  五、现在，立刻，做一次实践（这节最重要）

不管你选了哪个方案，**看到这里请立刻停下来，打开 Claude Code，做一次。** 不是看完就完事了，是**真的动手**。

###  你需要达到什么水平（面试时能用上的）

系统学完并动手练完之后，你应该能自信地讲出以下几点：

-   **能清晰描述需求** —— 用纯自然语言说清楚"我要一个什么样的页面/功能"，不需要会写代码
-   **能读懂并微调 AI 生成的代码** —— 改改文案、调调样式、修修简单逻辑，至少能指出"这里我想要的是 XX 效果"
-   **会借 AI 排错** —— 报错信息贴给 Claude Code，让 AI 帮你分析原因、给出修复方案，这也是 Vibe Coding 的核心能力
-   **能讲出自己的实践故事** —— 面试时不是背概念，而是说"我让 Claude Code 做了 XX，中间遇到 XX 报错，后来发现是 XX 原因，用 XX 方式解决的"。**有真实故事可讲，比空口说"我会"强十倍**

###  推荐你马上做的小任务（三选一）

打开 Claude Code，挑一个：

1.  做一个带标题和几个按钮的极简网页
2.  做一个本地运行的"聊天"界面样子（不用接真实 API，有界面就行）
3.  做一个简单的检索 Demo（后面第 4 章讲 RAG 时会用到这个基础）

**关键点**：

-   用自然语言描述需求，不要自己写代码
-   大概率一次跑不通，没关系，调几次
-   记下你卡住的地方和怎么解决的，这就是你的面试素材

**书中不会给"复制粘贴就能跑"的固定步骤**，因为 Claude Code 和依赖库更新太快，截图和命令很快就会过时。你亲手踩坑、亲手调通的经历，才是面试时最值钱的东西。

###  进阶小实验：感受 AI 的"不确定性"

如果你已经用 Claude Code 成功生成过一次，再做一件事：用**完全相同的一段话**描述需求，连续让 AI 生成 2～3 次，对比结果。

你会发现：

-   每次出来的东西都不一样
-   有时结构清晰，有时逻辑混乱
-   同样的输入，输出并不确定

这不是 bug，这是 AI 的本质——**概率生成**。作为 AI 产品经理，你的日常工作就是：

-   写出更精准的 Prompt，让输出更稳定可控
-   设计兜底和容错机制，让 AI 出错时产品不崩、用户不骂

做完这个实验，你对"AI 的能力边界在哪里"就有了真实的体感，比看十篇文章都管用。

##  六、你可能想问的

**Q1：没有梯子，ChatGPT 用不了怎么办？**

完全不影响。Kimi、DeepSeek、通义千问、文心一言，国内工具足够你学完整套内容。很多人没用过 ChatGPT 照样拿到了 AI PM offer。

**Q2：学生党 / 手头紧，怎么省着花？**

优先方案 A（Kimi + Claude Code 免费体验）。如果要用 DeepSeek API，它家的免费额度通常够用一段时间。

**Q3：DeepSeek API 怎么接到 Claude Code 里用？**

Claude Code 默认走 Anthropic 的 Claude 模型，但支持配置第三方 API（OpenAI 兼容格式）。具体操作搜「Claude Code 自定义模型配置」或直接问 Claude Code 自己。

##  七、自查清单：这节过关的标准

进入第 2 章之前，对照下面几项打勾：

-   \[ \] 至少有一个活跃的 AI 对话账号（Kimi / DeepSeek / ChatGPT 都行）
-   \[ \] Claude Code（或其他 AI 编程工具）已经装好了——这是硬门槛
-   \[ \] 用 Claude Code 独立完成了一次小任务（搭页面、做界面、写脚本都行）——**这是核心**
-   \[ \] 亲身体验过"说人话就能让 AI 写代码"的感觉
-   \[ \] 可选：注册了 v0.dev（UI 生成）
-   \[ \] 所有账号密码和 API Key 都妥善保存了

如果只有第 1 项打勾，后面几项都没做，**建议先回头补上**。现在的 AI PM 面试里，能讲清楚"我用 Claude Code 做过什么、怎么做的"的候选人，和只会说"我会用 ChatGPT 聊天"的候选人，竞争力完全不在一个层级。

本节只是 Vibe Coding 的"开胃菜"，目的是让你跑通第一次。Vibe Coding 作为 AI PM 的核心工作方式——包括它的演进历史、六步法工作流、L1-L3 分层放权机制、风险底线 SOP、四阶段升级路径——会在 **4.7 / 4.8** 做系统讲解。
