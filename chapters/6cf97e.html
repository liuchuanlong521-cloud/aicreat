核心考点

前言

嘿，老朋友，欢迎继续跟着学习！

如果你之前做过传统互联网产品的竞品分析，你可能已经有一套成熟的套路了：打开竞品App，截图、记录功能点、画功能对比表、写SWOT分析...这一套在AI产品面前，可能完全不够用。

为什么？因为AI产品的核心竞争力，往往不在界面上，而在模型里——你看不到它的模型架构，摸不准它的效果上限，甚至同一个功能，今天的体验和明天的体验可能都不一样（模型迭代了嘛）。更别提，AI产品的交互范式正在以月为单位快速变化：今天大家都在做聊天机器人，明天可能就都在做Agent了，后天又不知道会冒出什么新形态。

所以，AI产品的竞品分析，需要一套全新的方法论。这一节，我就把这套方法论完整教给你。咱们不仅要"看热闹"，更要"看门道"——透过产品表层，看清竞品的底层逻辑。Ready? Go!

# 一、AI产品竞品分析的特殊性

在讲具体方法之前，我们必须先理解：AI产品竞品分析，到底特殊在哪里？

# 1.1 模型黑盒：你看到的不是全部

传统产品的功能，基本是"所见即所得"的。竞品做了一个直播功能，你体验一遍，基本就能知道它有哪些能力、流程是什么、交互怎么设计的。

但AI产品不同。两个产品看起来都是"AI写作"功能，但背后的差异可能是天壤之别：

可见层传统产品AI产品
界面✅ 能看到✅ 能看到
功能流程✅ 能体验✅ 能体验
底层技术❌ 一般看不到❌ 绝对看不到
效果上限N/A❌ 很难判断
迭代方向相对可预测❌ 黑盒，难以预测

举例：

竞品A和竞品B都有一个"AI总结文档"的功能。

你测试了10个文档，发现竞品A的总结更精炼，竞品B的总结更全面。

但你知道为什么吗？

  • 可能是模型不同（GPT-4 vs Claude vs 自研模型）
  • 可能是Prompt工程不同（A的Prompt强调"精简"，B的强调"全面"）
  • 可能是后处理不同（A做了额外的压缩步骤，B做了信息补全）
  • 可能是训练数据不同（A用了更多新闻摘要数据，B用了更多学术论文数据）

这些因素，你作为外部观察者，几乎不可能准确判断。

核心考点

💡 应对策略

面对模型黑盒，竞品分析的重点要从"它用了什么技术"转向"它在什么场景下表现好/不好"。通过大量测试、收集badcase，建立对竞品能力边界的认知，比猜测它的技术路线更有价值。

# 1.2 交互范式变化快：今天的标杆，明天就过时

传统互联网产品的交互范式相对稳定。电商就是搜索+列表+详情+购物车+下单；社交就是关注+信息流+评论+点赞。这些基本范式十年没变过。

但AI产品的交互范式正在快速演进：

AI产品交互范式演进（2022-2025）：

2022年：单轮问答式
  └── 用户输入问题 → AI给答案 → 结束
  └── 代表：早期ChatGPT、各种AI问答工具

2023年：多轮对话式
  └── 支持上下文、追问、澄清
  └── 代表：ChatGPT、Claude、文心一言

2023年中：嵌入协作式
  └── AI嵌入到现有工作流中（文档、表格、代码编辑器）
  └── 代表：Notion AI、Microsoft Copilot、GitHub Copilot

2024年：Agent式
  └── AI能调用工具、执行多步骤任务
  └── 代表：AutoGPT、Devin、各种AI Agent平台

2024年中：多模态交互式
  └── 支持图文、语音、视频混合交互
  └── 代表：GPT-4V、Claude 3、Gemini

2025年：？
  └── 谁也不知道下一个范式是什么

⚠️ 注意

# 1.3 数据飞轮效应：先发优势可能被放大

这是AI产品竞品分析中最容易被忽视，但又最重要的一个点。

什么是数据飞轮？

数据飞轮对竞品分析的影响：

影响说明竞品分析启示
先发优势巨大先积累数据的竞品，模型效果会越来越好，后来者很难追赶不要只看当前功能，要看竞品的数据积累时间和规模
效果差距可能非线性扩大今天的差距10%，半年后可能是50%评估竞品的增长速度，而非静态的能力
垂直领域壁垒高在特定领域（医疗、法律、金融），专业数据难以获取分析竞品是否拥有独家数据资源

核心考点

💡 实战建议

在分析AI竞品时，一定要问这几个问题：

  1. 这个竞品有多少用户/数据了？ 数据飞轮转起来了吗？
  2. 它的数据是从哪来的？ 是公开数据还是独家数据？
  3. 这个领域的数据壁垒高吗？ 后来者容易获取同类数据吗？
  4. 如果我们要追赶，数据准备需要多长时间、多少成本？

# 二、AI竞品分析的六大维度

好了，理解了特殊性，我们进入实战。我总结了AI竞品分析的六大维度，建议你按照以下框架系统性地分析每一个竞品。

# 维度1：模型能力维度

这是AI竞品分析最核心、最独特的维度。传统产品没有这个维度。

# 分析框架

分析项关键问题分析方法
底层模型自研模型？调用第三方API？第三方用了什么模型？看官方公告、技术博客、API返回信息、行业报道
模型版本用的是最新版还是旧版？更新频率如何？定期测试同一问题，观察回答变化；关注官方更新日志
核心指标公开了哪些评测数据？在权威榜单排名如何？查论文、技术报告、公开Benchmark（如MMLU、HumanEval）
垂直优化是否针对特定领域做了微调/RAG/知识增强？测试专业领域问题，对比通用知识和专业知识的表现差异

# 实战测试方法

标准化测试集法：

构建你的"竞品测试题库"：

通用能力测试（适合所有AI产品）：
├── 逻辑推理题 × 5（测试推理能力）
├── 创意写作题 × 3（测试生成能力）
├── 长文本理解题 × 3（测试上下文窗口）
├── 多轮对话题 × 3（测试记忆和一致性）
├── 安全/价值观题 × 3（测试对齐质量）
└── 实时信息题 × 3（测试知识时效性）

专业能力测试（根据竞品领域定制）：
├── 如果你是分析AI法律助手 → 准备5个法律案例分析题
├── 如果你是分析AI医疗助手 → 准备5个症状诊断题
├── 如果你是分析AI编程助手 → 准备5个代码编写/调试题

测试原则：
1. 同一套题，同一时间，测试所有竞品
2. 记录回答内容、响应时间、输出长度
3. 邀请领域专家盲评（不知道哪个回答是哪个竞品的）
4. 定期复测（每月/每季度），观察竞品进步速度

💡 模型能力分析的关键洞察

不要只关注"谁得分高"，更要关注**"谁在什么类型的题目上表现好"**。这能帮你发现竞品的定位策略——它是走"全才"路线，还是走"专才"路线？它的能力短板在哪里？这些短板是不是你的机会？

# 维度2：功能场景维度

这是最接近传统竞品分析的维度，但AI产品的功能分析需要更关注"场景深度"。

# 分析框架

分析项关键问题输出物
场景覆盖竞品覆盖了多少个使用场景？场景清单
场景深度每个场景下有多少细分功能？流程是否闭环？功能拆解表
场景优先级竞品的主打场景是什么？资源倾斜在哪里？场景优先级判断
场景创新有没有竞品独创的场景？创新场景清单

从这个表格能读出什么？

  → 目标用户： already Notion用户

竞品C的策略：
  → 定位：通用写作辅助
  → 特点：功能较基础，缺乏差异化
  → 风险：容易被A或B替代

核心考点

💡 功能分析的关键洞察

做功能对比时，不要只数"谁的功能多"。要思考：

  1. 竞品的功能布局反映了什么战略选择？
  2. 哪些功能是"必备"的（大家都做），哪些功能是"差异化"的（只有它做）？
  3. 差异化功能是"真差异"还是"伪差异"？用户真的在乎吗？

# 维度3：交互体验维度

AI产品的交互体验，和传统产品有很大不同。传统产品讲"流程是否顺畅"，AI产品还要讲"对话是否自然""AI是否懂我""出错时怎么处理"。

# AI交互体验的三层评估

第一层：交互范式

范式类型特点适用场景代表产品
对话式聊天界面，自然语言交互通用问答、创意任务ChatGPT、Claude
嵌入协作式AI嵌入现有工具，边用边唤办公、编程、创作Copilot、Notion AI
Agent式AI自主规划、调用工具、执行任务复杂多步骤任务Devin、各类Agent平台
混合式多种范式组合综合场景大多数成熟AI产品

第二层：交互细节

对话式AI的交互细节检查清单：

输入体验：
├── 是否支持多模态输入（文字/语音/图片/文件）？
├── 输入框是否支持富文本（加粗、列表、代码块）？
├── 是否有快捷输入/提示词推荐？
├── 是否支持语音输入？识别准确率如何？
├── 是否支持上传附件？支持哪些格式？大小限制？

输出体验：
├── 输出速度如何？首字响应时间？
├── 是否流式输出（逐字显示）？
├── 输出格式是否丰富（代码高亮、表格、公式）？
├── 是否支持输出后编辑/复制/分享？
├── 是否支持重新生成/追问/否定？

错误/异常处理：
├── AI答错时，用户怎么反馈？（点赞/点踩/举报？）
├── AI拒绝回答时，理由是否清晰？
├── 网络超时/服务器繁忙时，提示是否友好？
├── 生成长内容中断时，是否支持"继续"？

上下文管理：
├── 是否显示对话历史？
├── 是否支持新建/切换会话？
├── 上下文窗口有多大？长对话会不会"失忆"？
├── 是否支持引用之前的对话内容？

第三层：情感体验

这是最容易被忽视，但最能形成差异化的层面。

体验要素好的体验差的体验
AI个性有温度、有个性、让人愿意聊冷冰冰、机械感、像在和机器人说话
容错包容AI答错了会道歉、会澄清AI答错了也理直气壮
掌控感用户随时知道AI在做什么、为什么AI像个黑盒，不知道它在干嘛
成长感用久了感觉AI更懂我了用了一个月和第一天没区别

核心考点

💡 交互体验分析建议

建议你亲自作为"深度用户"使用竞品至少一周。每天记录使用日志：什么时候用了？用来做什么？体验好的地方？体验差的地方？惊喜时刻？抓狂时刻？这些一手体验比任何功能对比表都更有价值。

# 维度4：数据资产维度

前面讲过数据飞轮，这里我们系统性地分析竞品的数据资产。

# 数据资产分析框架

分析项关键问题判断方法
数据规模有多少用户？产生了多少数据？公开数据（融资报告、发布会）、第三方估计（SimilarWeb、App Annie）
数据质量数据是否高质量、有标注？从输出质量反推；看是否有专业团队/合作方
数据独特性是否有竞品无法获取的独家数据？看行业壁垒、合作关系、数据积累时间
数据更新数据更新频率？时效性如何？测试实时信息类问题，看知识截止日期
飞轮状态是否已形成正向循环？看产品迭代速度、用户增长趋势、效果改进速度

# 数据资产类型对照表

数据类型价值获取难度典型拥有者
公开互联网数据基础能力低所有人（但有清洗成本）
用户交互数据持续优化模型中有用户基础的产品
专业标注数据垂直领域能力高有专业团队/合作方的产品
企业私有数据B端壁垒很高有企业客户的产品
多模态数据多模态能力高有图片/视频业务的产品
实时数据时效性能力中有搜索/信息流业务的产品

⚠️ 注意

数据资产分析往往涉及商业机密，很难拿到准确数字。但你可以通过间接证据来推断：

  • 竞品的产品迭代速度（飞轮转得快，迭代就快）
  • 竞品在垂直领域的效果（效果好通常意味着有高质量数据）
  • 竞品的合作伙伴（和谁合作，往往暗示数据来源）
  • 竞品的招聘方向（招标注团队？招数据工程师？）

# 维度5：成本效率维度

AI产品有一个传统产品不太需要考虑的问题：成本和效率。因为AI的推理是有成本的（算力、Token），而且这个成本直接影响商业模式。

# 成本效率分析框架

分析项关键问题评估方法
推理成本每次请求的成本是多少？如果调用第三方API，查公开定价；自研模型则需要估算
响应速度平均响应时间？高峰期是否变慢？实测（用脚本测100次取平均）
资源效率同样效果下，谁的模型更小/更快？技术报告中的参数规模、推理速度对比
商业模式如何覆盖成本？免费额度？订阅制？按量计费？直接看定价页面
成本趋势成本在上升还是下降？模型优化、量化、蒸馏等技术趋势

核心考点

💡 成本分析的关键洞察

竞品的定价策略往往反映了它的成本结构和战略选择：

  • 低价/免费 → 可能在烧钱换市场，或者有成本优势
  • 高价 → 可能成本确实高，或者走高端差异化路线
  • 按量计费 → 成本波动大，需要转嫁风险给用户
  • 订阅制 → 追求稳定的现金流，锁定长期用户

分析竞品的成本效率，能帮你判断：它能不能长期维持当前的服务质量？如果市场打起价格战，它有没有余地？

# 四、AI竞品分析的三大难点

即使有了方法论和工具，AI竞品分析仍然面临一些独特的困难。提前了解它们，你才能做好心理准备。

# 难点1：模型效果难以客观量化

问题： 同一个问题，问两次可能得到不同答案；不同的评估者对答案好坏的判断可能不同。

应对策略：

策略具体做法
标准化测试建立固定测试集，定期复测，记录变化趋势
盲测评估邀请多个评估者，隐去竞品名称，独立评分
A/B测试思维同样的任务，用不同竞品做，直接对比输出
关注badcase不要只看平均表现，要看 worst case 有多差
区分场景不同场景下效果可能差异很大，分别评估

# 难点2：交互体验主观性强

问题： "这个AI好不好用"非常主观。有人喜欢简洁，有人喜欢丰富；有人喜欢AI主动，有人喜欢AI被动。

应对策略：

策略具体做法
定义体验维度把"好不好用"拆成可评估的子维度（速度、准确性、可控性、容错性...）
多角色体验让新手用户、资深用户、专家用户分别体验，记录不同视角
任务完成度不要问"好不好用"，问"你完成这个任务了吗？花了多少时间？遇到了什么问题？"
情感曲线记录使用过程中的情绪波动（惊喜时刻 vs 挫败时刻）

# 难点3：技术路线差异大

问题： 两个竞品可能走了完全不同的技术路线，直接对比效果不公平，也不说明问题。

举例：

竞品A用大模型+Prompt Engineering做问答，竞品B用小模型+知识图谱+规则做问答。

测试结果：竞品A在开放性问题表现更好，竞品B在结构化问题表现更稳定。

怎么比？哪个更好？取决于你的目标场景是什么。

应对策略：

策略具体做法
场景化对比不要笼统比"谁更好"，要分场景比"在你的目标场景下谁更好"
拆解技术栈尽量分析竞品的技术架构，理解它为什么在某些场景表现好/不好
关注迭代速度技术路线没有绝对优劣，迭代速度快的团队可能后来居上
预判趋势结合技术趋势判断，哪种路线更有长期潜力

名师旁白

⚠️ 心态提醒

AI竞品分析不要追求"绝对准确"。因为信息不完整、技术变化快，你的分析结论必然有偏差。关键是：

  1. 建立系统性的分析框架，确保没有遗漏重要维度
  2. 持续跟踪更新，用新信息修正旧判断
  3. 关注趋势而非静态快照，看竞品在往哪个方向发展
  4. 保持谦逊，承认自己不知道的部分，不要做过度推断

# 写在最后

哇，这一节的内容密度不小吧？咱们来做个快速回顾：

  1. AI竞品分析的特殊性：模型黑盒让你看不透底层，交互范式快速变化让你赶不上，数据飞轮让先发优势越来越大——这三点决定了AI竞品分析必须是一套动态的、持续的、多维度的工作。

  2. 六大分析维度：模型能力（核心）、功能场景（基本面）、交互体验（差异化）、数据资产（护城河）、成本效率（可持续性）、生态壁垒（长期竞争力）。六个维度缺一不可。

  3. 工具与方法：功能拆解表、用户体验地图、SWOT分析、竞品追踪表——这些工具的目的不是让你"填表"，而是帮你结构化思考，确保没有遗漏。

  4. 三大难点：模型效果难量化、体验主观性强、技术路线差异大——承认这些困难的存在，用"持续测试+多维度评估+趋势判断"来应对。

  5. 两个案例：通用大模型的对比告诉我们"没有最好，只有最适合"；垂直领域的对比告诉我们"深度往往比广度更有壁垒"。

最后想叮嘱你一句：竞品分析的目的不是"抄"，而是"懂"——懂市场的格局、懂用户的期待、懂技术的边界、懂竞品的策略。真正的产品竞争力，来自于你在竞品分析基础上做出的差异化选择。
