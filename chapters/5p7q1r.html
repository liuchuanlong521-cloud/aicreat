# 阿里全面禁用Claude Code，Agent时代的安全边界在哪里？

7月3日，阿里内部人士确认：因存在"植入后门风险"，阿里将要求员工全面禁用 Anthropic 的 Claude Code，并将其列入高风险软件名单。禁令从 7 月 10 日起正式生效。未来阿里内部的 AI 办公需求，将由自家智能体产品 Qoder 满足。

这件事不只是一次软件替换，而是给所有产品经理提了个醒：Agent 时代，安全边界必须重新划定。

# 一、事件本身：Claude Code 被禁的核心原因

根据财新报道，海外论坛 Reddit 用户披露：Anthropic 在 Claude Code 中嵌入了类似间谍软件的隐藏代码，暗中针对中国用户采集数据，并通过植入用户提示词的方式上传用户信息，包括时区、代理服务器、疑似 AI 实验室关联信息等。

Anthropic 研究员回应称，这是今年 3 月上线的一项"试验机制"，初衷是防范未经授权的中间商滥用账号，以及抵御模型蒸馏窃取行为。

但不管初衷如何，结果是一样的：一个拥有高权限的桌面 Agent，可能在用户毫无察觉的情况下采集敏感信息。对于阿里这样把代码、数据、业务机密都堆在内部系统的公司来说，这是不可接受的风险。

# 二、为什么 Agent 的安全问题比传统 AI 工具更严重？

Claude Code 不是普通的代码补全插件，它是一个能自主执行复杂任务的 Agent：

  • 可以读取项目代码
  • 可以调用终端执行命令
  • 可以访问文件系统
  • 可以联网查询和操作

这意味着 Agent 的权限边界远超传统 SaaS 工具。一旦它"偷偷"上传数据，造成的损失可能是系统性的。

传统 AI 工具的安全模型是"输入一段文字，返回一段文字"，风险相对可控。Agent 的安全模型是"输入一个目标，自动执行多步操作"，它的风险在于：

  • 数据泄露：Agent 可能把内部代码、文档、聊天记录传到外部服务器
  • 权限滥用：Agent 可能调用超出预期的系统权限
  • 供应链攻击：Agent 本身可能成为被植入后门的环节
  • 行为不可解释：Agent 的执行路径复杂，出了问题难以追溯

# 三、大厂的应对：从"能用"到"可控"

阿里禁用 Claude Code，并用 Qoder 替代，本质上是在做一件事：把 Agent 纳入供应链安全和数据主权的管控范围。

这不是阿里一家的问题。腾讯、字节、华为等大厂都在做类似的布局：

  • 自研模型和 Agent 工具
  • 私有化部署
  • 权限隔离和审计日志
  • 零信任访问机制

Agent 越强大，越需要被关进"有围墙的花园"。

# 四、对产品经理的启示

  1. Agent 的权限设计必须最小化。 不要给一个 Agent 超过它任务所需的权限。能读就不要写，能读局部就不要读全部，能在沙箱运行就不要进生产环境。

  2. 数据出境和存储位置是硬约束。 企业级 Agent 必须明确数据存在哪里、会不会被用于模型训练、会不会被第三方访问。这是 B 端客户采购前的必答题。

  3. 安全要从产品设计的第一天就考虑。 不是等出了事再加审计日志，而是在设计 Agent 的每一步操作时，都考虑"如果这里被滥用，后果是什么"。

  4. 自研 vs 第三方的平衡需要重新评估。 过去企业可能倾向于采购最好的第三方工具。但在 Agent 时代，核心生产力工具的自研或可控部署，会成为越来越多大厂的选择。

  5. Agent 的行为需要可解释、可审计。 用户和企业都需要知道：Agent 做了什么、调用了什么、修改了什么、为什么这么做。黑箱 Agent 在企业场景走不远。

# 最后

阿里禁用 Claude Code，表面上是中美科技公司之间的一场信任危机，本质上是 Agent 时代安全范式的提前演练。

Agent 的能力越强，它对企业数据和系统的影响力就越大。产品经理在设计 Agent 产品时，不能只问"它能做什么"，更要问"它不该做什么""出了事怎么追溯""用户怎么信任它"。

在 Agent 真正大规模进入企业之前，先把安全边界画清楚，可能是比功能创新更紧迫的事。

思考题：如果你的产品需要接入一个第三方 Agent 能力，你会从哪些维度评估它的安全风险？
