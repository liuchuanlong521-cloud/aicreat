核心考点

前言

如果你之前写过传统互联网产品的PRD，可能会觉得"这有什么难的？"但我要告诉你，AI PRD和传统PRD有着本质的区别。 传统PRD描述的是一个确定性系统：用户点击A按钮，系统执行B逻辑，展示C结果。一切都是可预期的、可精确描述的。但AI PRD描述的是一个概率性系统：用户输入一个问题，模型"可能"给出正确答案，"可能"给出错误答案，"可能"直接" hallucinate（幻觉）"出不存在的信息。你不能在PRD里写"模型输出正确答案"，因为这不是一个确定性的功能，而是一个概率性的表现。 所以，AI PRD需要在传统PRD的基础上，增加很多AI特有的模块：模型评估标准、数据需求、兜底策略、效果监控……这些在传统PRD里要么没有，要么非常简单。 这一节，我会把AI PRD拆成10大核心模块，每个模块都会给你模板和示例。最后，我还会给你一个完整的AI PRD案例。读完这一节，你就能写出一份让算法工程师、开发工程师、测试工程师都能看懂的AI PRD。

# 一、AI PRD与传统PRD的本质区别

# 1.1 核心区别一览

对比维度传统PRDAI PRD
系统性质确定性系统概率性系统
输出描述"系统返回用户订单列表""模型生成回答，准确率目标≥85%"
质量衡量功能是否实现（Pass/Fail）准确率、召回率、F1、用户满意度
边界处理明确的异常分支模型幻觉、置信度低、生成内容违规
依赖资源主要依赖开发资源额外依赖数据、算力、模型迭代
迭代方式修Bug即可需要重新训练、调参、换模型
测试方式固定用例，预期确定结果统计评估，结果有波动
上线标准功能通过测试即可上线需达到效果指标阈值才能上线

# 1.2 为什么AI PRD更难写？

难点一：效果的不确定性

传统PRD里，你可以写："点击提交按钮后，系统显示'提交成功'。"这是100%确定的。但AI PRD里，你不能写："用户输入问题后，模型给出正确答案。"因为模型不是100%正确的。

所以AI PRD需要用统计性语言描述效果："在测试集上，模型回答的准确率应≥85%，幻觉率应≤5%。"

难点二：需要跨学科沟通

传统PRD主要是产品经理和开发工程师之间的沟通。但AI PRD涉及更多角色：

这意味着AI PRD需要覆盖更广泛的内容，满足不同角色的信息需求。

难点三：需要定义"好"的标准

传统功能"好"或"不好"是明确的：按钮点击后跳转对吗？数据展示对吗？但AI功能"好"或"不好"是模糊的。你需要在PRD里明确定义什么是"好"的回答：

评估维度传统功能AI功能
正确性对/错准确率、召回率
速度响应时间<200ms首Token延迟<500ms
稳定性100%可用99.9%可用，效果波动在±5%内
用户体验主观评分4.5+用户满意度评分4.0+

# 1.3 AI PRD的10大核心模块

一份完整的AI PRD应该包含以下10个模块：

  1. 需求背景与目标
  2. 用户场景与角色
  3. 模型目标与评估标准
  4. 数据需求
  5. 产品功能设计
  6. AI交互设计
  7. 兜底策略
  8. 效果评估方案
  9. 技术方案概述
  10. 风险与合规

下面，我们逐一详细拆解。

# 示例：智能客服机器人

# 1. 需求背景与目标

# 1.1 背景

当前人工客服团队日均接待量5000+，其中约60%为重复性高频问题（如"怎么修改密码""订单什么时候到"）。人工客服响应平均时长3分钟，高峰期用户等待超10分钟，NPS评分中"响应速度"项得分仅3.2/5。

竞品分析显示，Top 3竞品均已上线智能客服，平均解决率65%，平均响应时间<10秒。

# 1.2 目标

  • 业务目标：降低人工客服接待量30%，人工客服平均响应时长降至1分钟内
  • 用户目标：用户问题得到即时响应，80%的常见问题无需转人工
  • 技术目标：意图识别准确率≥90%，回答满意度≥4.0/5

# 1.3 成功指标

指标类型指标名称当前值目标值衡量方式
业务指标人工客服接待量5000/天3500/天后台统计
业务指标单客服务成本￥8/次￥5/次财务核算
用户指标平均响应时长180秒<10秒系统计时
用户指标用户满意度3.8/54.2/5会话后评价
技术指标意图识别准确率-≥90%测试集评估
技术指标回答满意度-≥4.0/5人工抽检

# 1.4 范围

  • ✅ 包含：电商场景下的售前/售后高频问题自动应答
  • ✅ 包含：无法回答时的转人工机制
  • ❌ 不包含：复杂客诉处理（需人工介入）
  • ❌ 不包含：多轮带状态的复杂业务流程（如下单、退款）
  • ❌ 不包含：语音客服（本期仅文字）

# 2.2 使用场景

# 场景1：查询物流信息

  • 触发条件：用户点击"联系客服"，或发送消息
  • 用户输入："我的订单到哪了？"
  • 系统响应：
    1. 意图识别：物流查询
    2. 实体抽取：提取"我的订单"→关联用户最近订单
    3. 生成回答："您的订单 #20240526001 已到达【北京市分拣中心】，预计明天送达。"
    4. 提供快捷操作："查看详情" "催件" "联系快递员"
  • 预期结果：用户获得物流信息，无需转人工

# 场景2：申请退货

  • 触发条件：用户表达退货意愿
  • 用户输入："这个衣服尺码不对，想退"
  • 系统响应：
    1. 意图识别：退货申请
    2. 实体抽取：商品="衣服"，原因="尺码不对"
    3. 条件判断：该商品是否在7天无理由退货期内？是
    4. 生成回答："该商品支持7天无理由退货。请点击【发起退货】，按指引寄回商品。"
    5. 提供操作入口
  • 预期结果：用户自助完成退货申请，或明确下一步操作

# 示例：智能客服机器人

# 3. 模型目标与评估标准

# 3.1 模型任务定义

本项目涉及多个模型子任务：

子任务1：意图识别（Intent Classification）

  • 任务类型：多分类

  • 输入：用户原始query文本

  • 输出：意图类别 + 置信度

  • 意图类别定义：

    意图ID意图名称说明示例
    I001查询物流查询订单物流状态"我的快递到哪了"
    I002申请退货表达退货/退款意愿"我要退货"
    I003活动咨询询问优惠活动"满减怎么用"
    I004账户问题登录/密码/支付问题"忘记密码"
    I005商品咨询询问商品信息"这件有M码吗"
    I999其他/未知无法归类或闲聊"你好"

子任务2：实体抽取（Named Entity Recognition）

  • 任务类型：序列标注

  • 输入：用户原始query文本

  • 输出：实体列表（类型+值）

  • 实体类型定义：

    实体类型说明示例
    ORDER_ID订单号"20240526001"
    PRODUCT商品名称"红色连衣裙"
    TIME时间"昨天买的"
    AMOUNT金额"199元"

子任务3：回答生成（Response Generation）

  • 任务类型：文本生成
  • 输入：用户query + 意图 + 实体 + 相关知识
  • 输出：自然语言回答文本

# 3.2 评估指标

指标定义目标值最低可接受值测试方式
意图识别准确率正确识别意图的query占比≥92%≥85%人工标注测试集
意图识别召回率所有意图query中被正确识别的占比≥90%≥82%人工标注测试集
Top-3意图覆盖率正确答案在Top-3中的占比≥98%≥95%人工标注测试集
实体抽取F1精确率和召回率的调和平均≥85%≥75%人工标注测试集
回答满意度用户对回答的评分(1-5)≥4.0≥3.5会话后弹窗评价
回答相关性回答与用户问题的相关程度(1-5)≥4.2≥3.8人工抽检
幻觉率回答中包含错误/编造信息的比例≤3%≤5%人工抽检
平均响应时间从接收请求到返回首字的时间<800ms<1500ms系统监控
问题解决率用户未转人工即结束会话的比例≥65%≥55%系统统计

# 3.3 评估数据集

意图识别测试集：

  • 规模：2000条query（每类意图约250-400条）
  • 来源：历史客服会话脱敏数据 + 人工构造边界case
  • 标注标准：每条query由2名标注员独立标注，不一致由第3人仲裁
  • 更新频率：每月补充当月新出现的query类型

回答质量评估集：

  • 规模：500个对话轮次

  • 评估维度：准确性、完整性、友好度、Actionability

  • 评分标准：

    分数标准
    5分完全正确，用户可直接按此操作
    4分基本正确，少量信息需补充
    3分部分正确，用户需要进一步确认
    2分有明显错误，但方向大致正确
    1分完全错误或答非所问

# 3.4 A/B测试方案

项目说明
对照组现有FAQ匹配系统

# 7.2 降级方案

三级降级体系：

Level 1（正常）: 模型生成回答 ↓ 意图置信度低/模型异常 Level 2（轻度降级）: FAQ匹配回答 ↓ FAQ无匹配/服务超时 Level 3（重度降级）: 兜底话术 + 转人工引导 ↓ 服务完全不可用 Level 4（灾备）: 展示"客服繁忙" + 留言功能

降级级别触发条件系统行为用户感知
L1-正常所有服务正常模型生成回答正常AI对话
L2-FAQ降级意图置信度<0.6或模型超时切换至FAQ关键词匹配回答可能较生硬，但基本可用
L3-兜底降级FAQ无匹配或连续失败返回兜底话术，建议转人工"抱歉，这个问题比较复杂，建议您转接人工客服"
L4-灾备整体服务不可用关闭AI入口，仅保留留言"客服系统维护中，您可以留言，我们会尽快回复"

# 7.3 人工介入机制

主动转人工（系统判断）：

  • 连续3次无法有效回答
  • 命中投诉/维权/情绪激烈意图
  • 敏感问题无法自动处理

被动转人工（用户主动）：

  • 始终提供"转人工"按钮，随时可点击
  • 用户输入"人工""客服""找人工"等关键词时，立即转接

转人工流程： 触发转人工 ↓ 保存当前会话上下文（转给人工客服查看） ↓ 排队等待（显示排队人数和预计等待时间） ↓ 接入人工客服（人工可看到AI对话历史） ↓ 人工处理完成 ↓ 可选择"AI继续跟进"或"结束会话"

# 7.4 错误提示文案

场景提示文案设计原则
没理解用户"抱歉，我没太明白您的问题。您可以尝试问我：\n1. 查询物流\n2. 申请退货\n3. 优惠券怎么用"给方向，不道歉过度
需要更多信息"为了更准确地帮您，请问您能提供一下订单号吗？"引导用户提供关键信息
超出能力范围"这个问题比较复杂，我帮您转接人工客服处理吧~"不暴露技术限制，自然过渡
服务繁忙"当前咨询人数较多，您可以稍后再试，或留言给我们"真诚说明，提供替代方案
敏感问题"您的问题涉及特殊处理流程，建议您联系人工客服或拨打400-xxx"不拒绝，给出口

竞品快速跟进高中1. 深耕业务场景 2. 快速迭代 3. 数据飞轮产品

# 10.2 内容安全

输入审核：

  • 用户输入经过敏感词检测
  • 命中敏感词的输入不进入模型，直接返回安全提示

输出审核：

  • 模型输出经过敏感词过滤
  • 涉及医疗、法律、金融建议的输出，强制添加免责声明
  • 每日人工抽检100条回答

应急机制：

  • 发现严重安全问题时，可一键关闭AI回答，全部转人工

# 10.3 隐私保护

  • 用户手机号、地址等PII信息在传入模型前脱敏
  • 模型训练数据不包含可识别个人的信息
  • 用户对话记录保存90天后自动删除（法律法规要求的除外）
  • 用户可主动删除自己的对话历史

# 10.4 偏见控制

  • 训练数据覆盖不同地区、不同年龄、不同性别的用户query
  • 定期审查模型回答是否存在性别/地域/年龄偏见
  • 对投诉中涉及"不公平对待"的case重点分析

# 三、AI PRD的写作原则

写完10个模块，你还需要掌握3条核心写作原则：

# 原则一：具体而非模糊

❌ 模糊写法✅ 具体写法
"模型效果要好""意图识别准确率≥90%，回答满意度≥4.0/5"
"响应要快""P95响应时间<800ms"
"覆盖常见问题""覆盖Top 50高频意图，覆盖率达80%以上"
"用户反馈不错""会话满意度评分≥4.0，点踩率<5%"

# 原则二：可测量而非主观

每个目标、每个标准，都应该是可以被客观测量的。

❌ 主观写法✅ 可测量写法
"提高用户体验""平均会话时长缩短30%，满意度提升0.5分"
"模型要稳定""服务可用性≥99.9%，错误率<1%"
"回答要准确""幻觉率<3%，事实准确率>85%"

# 原则三：可迭代而非一次性

AI产品不是上线就完了，而是需要持续迭代。PRD要体现这种迭代思维。

迭代思维在PRD中的体现：

  • 定义MVP范围：第一期只做核心功能，后续迭代
  • 定义迭代触发条件：什么指标不达标时启动迭代
  • 预留迭代资源：不要把资源100%投入第一期
  • 数据驱动迭代：定义需要收集什么数据来指导迭代
迭代阶段范围目标
MVP5个高频意图 + FAQ回答验证核心能力，快速上线
V1.1扩展到15个意图 + 模型生成提升覆盖率
V1.2多轮对话 + 上下文理解提升复杂问题解决率
V2.0全量意图 + 个性化推荐全面替代基础人工客服

# 四、完整AI PRD案例：AI简历诊断助手

下面是一个完整的AI PRD案例，场景是"AI简历诊断助手"。这个案例比上面的客服案例更简洁，但结构完整，供你参考。

# AI简历诊断助手 - PRD

# 1. 需求背景与目标

# 1.1 背景

求职用户上传简历后，缺乏专业的简历优化建议。人工简历诊断服务单价￥199/次，产能有限，无法满足大量用户的诊断需求。

# 1.2 目标

  • 业务目标：简历诊断服务成本降低80%，日服务量从100人提升到10000人
  • 用户目标：用户上传简历后，3分钟内获得专业诊断报告
  • 技术目标：诊断建议准确率≥85%，用户采纳率≥60%

# 1.3 成功指标

指标目标值
日均诊断量≥5000份
平均响应时间<3分钟
用户采纳建议率≥60%
用户满意度≥4.2/5
诊断准确率≥85%

# 2. 用户场景与角色

角色描述诉求
应届生A第一次写简历，不知道格式和内容标准获得简历基础框架建议
职场人B3年经验，想跳槽，简历竞争力不足获得针对性优化建议
转行者C从A行业转B行业，简历不会写获得转行简历写法建议

核心场景：用户上传PDF/Word简历 → AI解析内容 → 生成诊断报告 → 用户查看并采纳建议

# 3. 模型目标与评估标准

# 3.1 模型任务

  • 任务1：简历信息抽取（姓名、联系方式、工作经历、项目经验、技能等）
  • 任务2：简历质量评估（结构完整性、内容充实度、亮点突出度）
  • 任务3：优化建议生成（针对每段经历给出具体修改建议）

# 3.2 评估指标

指标目标值最低值
信息抽取准确率≥90%≥85%
质量评分一致性与人工评分相关性≥0.8≥0.7
建议可采纳率≥70%≥60%
生成幻觉率≤5%≤8%

# 3.3 A/B测试

  • 对照组：人工诊断（抽样）
  • 实验组：AI诊断
  • 核心指标：用户采纳率、满意度

# 4. 数据需求

数据类型数据量来源
脱敏简历10万份历史用户上传简历（已授权）
人工诊断报告5000份人工诊断师历史报告
标注数据2000份人工标注简历质量分数

# 5. 产品功能设计

# 5.1 功能列表

功能优先级
简历上传（PDF/Word/图片）P0
简历内容解析P0
多维度评分（结构/内容/亮点/匹配度）P0
逐段优化建议生成P0
优化前后对比P1
一键生成优化版简历P1
行业/岗位匹配度分析P1

# 5.2 核心流程

用户上传简历 ↓ 系统解析简历内容 ↓ 生成评分报告（雷达图展示） ↓ 生成逐段优化建议 ↓ 用户查看报告 ↓ 用户选择采纳/忽略每条建议 ↓ 用户导出优化版简历（P1）

# 6. AI交互设计

  • 进度展示：诊断过程中展示进度条"正在分析简历结构...→正在评估内容质量...→正在生成建议..."
  • 置信度展示：每条建议旁标注"AI建议，请结合实际情况判断"
  • 反馈机制：每条建议可点"有帮助"/"没帮助"
  • 人工兜底：提供"升级为人工诊断"入口

# 7. 兜底策略

场景处理
简历解析失败提示"简历格式较复杂，建议手动输入关键信息"
建议质量低用户点踩>3次时，提供免费人工诊断券
敏感信息检测到身份证号等敏感信息，提示"已自动脱敏处理"
服务繁忙排队处理，预计等待时间xx分钟

# 8. 效果评估方案

  • 每日监控：诊断量、成功率、响应时间
  • 每周复盘：采纳率、满意度、Bad Case
  • 每月迭代：模型效果、新增场景支持

# 9. 技术方案概述

任务方案
简历解析OCR（图片）+ 文本抽取模型
质量评估微调BERT做分类+评分
建议生成GPT-4 API + RAG（检索优秀简历片段）

# 10. 风险与合规

  • 隐私风险：简历含敏感个人信息，需严格脱敏，用户授权后处理
  • 幻觉风险：建议可能不符合行业实际，需添加免责声明
  • 合规：符合《个人信息保护法》，用户可删除数据

# 五、写在最后

好了，到这里，你已经完整学习了AI PRD的10大核心模块、3条写作原则，还看了两个完整的案例。

让我们回顾一下AI PRD与传统PRD的核心差异：

传统PRDAI PRD
描述确定性系统描述概率性系统
功能Pass/Fail效果用统计指标衡量
边界是异常分支边界是模型幻觉和不确定性
上线=结束上线=开始（持续迭代）

写AI PRD时，最核心的思维转变是：从"精确描述功能"转变为"精确描述预期效果+兜底策略"。你不能控制模型每一次输出什么，但你可以控制：模型输出的平均质量、模型失效时怎么办、怎么持续监控和改进。

最后给你一份AI PRD的自查清单，写完PRD后对照检查：

  • [ ] 是否定义了明确的模型评估指标和目标值？
  • [ ] 是否定义了最低可接受的指标阈值？
  • [ ] 数据需求是否明确（来源、量级、质量）？
  • [ ] 是否有完整的兜底策略（多级降级）？
  • [ ] 是否定义了模型失效时的用户感知？
  • [ ] 是否包含内容安全和合规方案？
  • [ ] 是否定义了上线后的监控指标和迭代标准？
  • [ ] 是否标识了AI身份？
  • [ ] 是否提供了用户反馈机制？
  • [ ] 技术方案是否经过算法团队确认？
