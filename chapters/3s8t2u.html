# 千问豆包下线"智能体"，腾讯却 All in：两种智能体的分野

7月4日，阿里千问和字节豆包先后通知用户：7月15 日起，App 内的"智能体"功能将下线。几乎同时，腾讯却在加速推进 Agent：混元 Hy3 强化 Agent 能力、元宝上线免费 Agent 功能、WorkBuddy 月访问量冲到 885 万。

看起来矛盾吗？其实并不矛盾。下线的"智能体"和腾讯在做 Agent，根本不是一个物种。

# 一、新闻澄清：千问豆包下线的是什么？

根据财新报道，千问和豆包下线的"智能体"功能，指的是早期依托知识库打造的特色 AI 聊天机器人。

典型使用场景包括：

  • 角色扮演和陪聊
  • 英语陪练
  • 特定场景文案产出
  • 用户用简单 prompt 自建的人设型机器人

比如用户在豆包里创建一个"中学老师"智能体，它会以老师的口吻回答问题。这类产品的核心是陪伴感和人格化，而不是完成任务。

而下线的节点，正好撞上 7 月 15 日施行的《人工智能拟人化互动服务管理暂行办法》。UGC 角色扮演内容涉及的软色情、擦边、情感诱导等问题，监管成本极高。

# 二、腾讯在做的是什么？任务型 Agent

腾讯的 Agent 产品矩阵完全是另一条路线：

  • 元宝 Agent：一句话生成 PPT、Word、PDF
  • WorkBuddy：桌面智能体工作台，自动操作电脑、连接微信/企业微信
  • CodeBuddy：AI 编程助手，提升研发效率
  • QClaw：消费级 AI 智能体，直连微信

这些产品的共同点是：不陪你聊天，帮你干活。

维度千问/豆包下线的"智能体"腾讯在做 Agent
核心形态角色化聊天机器人任务执行工具
用户需求陪伴、娱乐、新鲜感提效、完成工作
内容来源UGC，用户自建人设平台定义工具和流程
商业逻辑流量 + 广告/会员效率提升 + 企业付费
监管风险高：UGC 角色扮演内容难控低：任务型、受控场景

# 三、为什么陪伴型被监管，任务型在崛起？

这不是大厂在"抛弃智能体"，而是在淘汰一种特定形态的智能体。

陪伴型智能体的问题在于：

  • 用户价值弱：新鲜感一过，留存断崖式下跌
  • 商业闭环差：用户不愿为陪聊持续付费
  • 合规成本高：UGC 内容全天候风控，投入产出倒挂

任务型 Agent 的优势在于：

  • 解决真实问题：写报告、写代码、处理工单、预订服务
  • 企业愿意付费：只要 ROI 算得过来，企业采购意愿强
  • 场景可控：运行在明确的业务流程中，安全合规更容易落地

# 四、对产品经理的启示

  1. 不要把所有"智能体"混为一谈。 陪伴型、任务型、工具型、平台型，不同形态的产品逻辑完全不同。分析产品前，先界定清楚它到底是什么。

  2. 用户为"结果"付费，不为"人设"付费。 角色扮演可能带来短期活跃，但长期商业价值取决于它能否交付可量化的结果。

  3. 合规是产品形态的决定性变量。 当监管成本超过业务价值时，再有趣的产品形态也会被砍掉。产品经理做设计时，要把合规当作前置约束。

  4. C 端 Agent 的机会在"办事"，不在"陪聊"。 用户真正需要的不是更懂自己的"电子宠物"，而是能替代重复劳动、完成实际任务的"数字员工"。

  5. 看大厂动作要看清底层逻辑。 千问豆包下线某个功能，不等于放弃 Agent。腾讯 All in Agent，也不等于所有 Agent 方向都对。关键是看它做的是什么类型的 Agent。

# 最后

"智能体"这个词在过去一年被用得太泛了，以至于很多人忘了它本来可以指很多种完全不同的产品。

千问和豆包下线的，是陪伴型 UGC 智能体这个特定形态。它的问题不是"智能体"三个字，而是它的产品逻辑本身站不住脚。

腾讯、阿里、字节真正的战场，已经转移到了任务型 Agent——能调用工具、完成任务、交付结果的 Agent。

产品经理要学会区分概念和实体。风口的名称会变，但产品的基本规律不会变：解决真实问题、商业闭环成立、合规风险可控，才值得长期投入。

思考题：你手机里安装的 AI 产品中，哪些属于"陪伴型"，哪些属于"任务型"？你更愿意为什么样的能力付费？
