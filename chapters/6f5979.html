核心考点

前言

大家好，欢迎来到第5章的第4节。前面我们聊过了Token成本、如何挖掘AI需求、如何对标竞品，今天我们要聊一个很多AI产品经理都会踩坑的话题——如何合理评估AI产品的需求。

说实话，评估需求这件事，在传统互联网产品里就已经够复杂了。但AI产品又给它加了好几层"地狱难度"：模型效果不确定、成本像黑洞一样深不见底、技术迭代速度快到上周的结论这周就作废。我见过太多团队，因为一个"看起来很美"的AI需求，投入了半年开发，最后发现模型准确率只有60%，用户根本不买账。

所以这一节，我想把自己踩过的坑、看过的案例、总结的方法，毫无保留地分享给你。我们会聊一个四维评估框架、几套实用的评估工具、完整的评估流程，还有两个完整的实战案例。读完这一节，你拿到一个AI需求时，心里会有一杆清晰的秤。

# 一、为什么AI产品需求的评估比传统产品更复杂

在深入方法论之前，我们先来理解一个根本问题：AI产品需求评估到底难在哪里？

# 1.1 效果的不确定性：模型不是代码，不会"按逻辑执行"

传统软件的功能是确定性的。你写一段代码 if (user.age > 18) { allow(); }，只要条件满足，结果一定是允许。但AI模型是概率性的——你喂给它同样的输入，输出可能每次都不一样。

对比维度传统软件功能AI模型功能
输出特性确定性（Deterministic）概率性（Probabilistic）
可预测性输入相同，输出一定相同输入相同，输出可能不同
边界行为明确的异常分支模糊的"幻觉"或"胡言乱语"
质量衡量功能是否实现（0/1）准确率、召回率、F1等连续指标
迭代方式修复Bug即可需要重新训练、调参、换模型

这意味着，当你评估一个"AI自动生成会议纪要"的需求时，你不能简单地问"能做吗？"，而必须问"能做到多好的程度？80%的准确率用户能接受吗？"

# 1.2 成本不可控：算力成本和数据成本是"无底洞"

传统产品的成本主要是人力成本和服务器成本，这些相对可控。但AI产品多了两块巨大的成本：

算力成本：

  • 训练成本：一个中等规模的LLM微调任务，GPU集群跑一周，费用轻松上万元
  • 推理成本：每次用户调用都消耗Token，用户量上来后，月度API账单可能高达数十万
  • 实验成本：模型选型、超参调优、A/B测试，每次实验都是真金白银

数据成本：

  • 数据采集：获取高质量标注数据的成本极高
  • 数据标注：医学影像标注需要专业医生，一条标注可能几百元
  • 数据清洗：原始数据80%的时间都花在清洗上

名师旁白

成本黑洞警示

很多产品经理在评估需求时，只考虑了"开发成本"，完全忽略了"数据准备成本"和"模型迭代成本"。结果项目做到一半，发现预算只够训练一版模型，根本没有余力做优化。

# 1.3 技术迭代快：今天的最优解，明天可能被淘汰

AI领域的技术迭代速度快得惊人。2023年大家还在用RAG+GPT-3.5做知识库问答，2024年GPT-4o和多Agent架构就让很多方案彻底过时。这意味着：

  • 你的技术方案可能在项目开发期间就被新技术颠覆
  • 今天评估"不可行"的需求，半年后可能变得可行
  • 模型能力的跃迁可能让某些"高成本方案"变得廉价

核心考点

应对策略

不要把技术方案评估当作"一次性"的。建立技术雷达机制，每季度复盘一次技术选型，保持对新技术（新模型、新框架、新方法论）的敏感度。

# 二、AI需求评估的四维框架

面对上述复杂性，我总结了一个四维评估框架，从四个维度系统性地审视每一个AI需求。

# 2.1 用户价值维度：这个需求到底值不值得做？

用户价值是需求评估的起点。再酷的技术，如果用户不需要，也是白搭。

# 2.1.1 需求真实性：是真需求还是伪需求？

判断方法：

检验方法具体操作通过标准
用户访谈访谈至少10个目标用户超过70%的用户表示有这个痛点
场景还原让用户描述最近一次遇到该问题的场景用户能清晰描述具体场景、时间、频率
替代方案调研用户现在怎么解决这个问题？用户已经在用某种低效方式解决，或因为麻烦而忍受
付费意愿测试直接问"如果收费X元/月，你会用吗？"超过30%的用户表示愿意付费

伪需求陷阱

伪需求陷阱

"我们做了个AI功能，用户一定会喜欢"——这是最危险的假设。很多AI产品之所以失败，不是因为技术不行，而是因为解决了一个不存在的问题。

经典案例：某大厂曾推出"AI智能衣架"，能根据天气推荐穿衣。技术很酷，但用户痛点不够强烈——大多数人早上选衣服只需要看窗外一眼。产品上线后DAU惨淡。

# 2.1.2 需求频次：是高频刚需还是低频偶发？

频次决定了产品的天花板。

频次级别典型场景产品策略
高频（每天多次）AI搜索、智能输入法、智能客服核心功能，重点投入
中频（每周几次）AI周报生成、智能文档校对增值功能，适度投入
低频（每月几次）AI年终总结、智能报税辅助功能，轻量化实现
极低频（每年几次）AI婚礼致辞生成、AI墓志铭谨慎评估，可能不值得

# 2.1.3 痛点强度：用户有多"痛"？

痛点强度可以用 "不用这个产品的代价" 来衡量：

痛点级别表现举例
致命痛不用会严重影响工作/生活，或造成损失医生不用AI辅助诊断，可能漏诊；客服不用智能回复，响应超时扣钱
强烈痛不用会很麻烦，效率大幅下降程序员不用AI代码补全，编码速度慢50%
中度痛不用会有些许不便，但可以忍受不用AI写邮件，自己写多花5分钟
轻微痛不用几乎没感觉不用AI生成朋友圈文案

核心考点

判断技巧

如果用户描述痛点时用了"每次都要...""特别烦...""浪费我很多时间..."这样的表述，说明痛点强度较高。如果只是"如果能...就更好了"，说明是锦上添花。

# 2.1.4 用户付费意愿：愿意为这个功能付多少钱？

这是最直接的价值验证。

付费意愿测试方法：

  1. 直接询问法："如果这项服务收费99元/月，你愿意付费吗？"
  2. 选择实验法：给用户几个选项，看他们在不同价格下的选择
  3. 预付费测试：在MVP阶段就设置付费墙，看转化率
付费意愿等级用户占比商业策略
高（>50%愿意付费）核心用户群可直接收费，或作为付费功能
中（20%-50%）潜在付费用户免费试用+付费升级模式
低（<20%）大众用户作为引流功能，靠其他方式变现

# 2.2 技术可行性维度：我们能不能做出来？

用户价值再高的需求，如果技术上做不出来或成本过高，也只能放弃或延后。

# 2.2.1 当前模型能力是否满足？

这是AI需求评估最核心的技术问题。你需要回答：现有的大模型/算法，能不能达到产品要求的准确率？

评估步骤：

Step 1: 明确任务类型
  ├─ 文本生成类（写文章、写代码、写邮件）
  ├─ 信息提取类（NER、关系抽取、摘要）
  ├─ 分类判断类（情感分析、意图识别、审核）
  ├─ 问答对话类（知识问答、客服、导购）
  └─ 多模态类（图像理解、语音转写、视频分析）

Step 2: 查看SOTA水平
  ├─ 查阅该任务在公开数据集上的SOTA准确率
  ├─ 了解商用API（GPT-4、Claude、文心等）在该任务的表现
  └─ 评估差距：SOTA准确率 vs 产品要求的准确率

Step 3: 做快速PoC验证
  ├─ 准备100条真实业务数据
  ├─ 调用商用API或开源模型跑测试
  └─ 记录准确率、延迟、成本

# 2.2.2 数据是否足够？

数据是AI模型的"燃料"。评估数据可用性要考虑：

数据维度评估问题风险等级
数据量是否有至少几千到几万条标注数据？量不够→高风险
数据质量数据是否准确、完整、无噪声？质量差→高风险
数据获取难度数据是否容易获取？是否需要特殊授权？难获取→高风险
标注成本标注一条数据需要多少成本和时间？成本高→需谨慎
数据隐私是否涉及用户隐私/商业机密？涉隐私→需合规方案

名师旁白

数据陷阱

很多产品经理会想当然地认为"我们有数据"。但实际情况往往是：

  • 有原始日志，但没有标注
  • 有标注，但标注标准不统一
  • 有数据，但质量很差（大量噪声、错误标签）
  • 有数据，但分布和实际场景不一致

建议：在评估阶段就要求算法团队做一次数据探查（Data Exploration），给出数据质量报告。

# 2.2.3 算法团队能力匹配度

评估维度关键问题判断标准
技术储备团队是否做过类似任务？有成功经验→低风险
人员配置是否有足够的算法工程师？至少2-3名核心算法人员
工程能力是否有ML工程化经验？模型上线、监控、迭代流程是否成熟
研究能力是否需要前沿研究创新？如果是SOTA级创新，需要研究型团队

# 2.2.4 算力成本评估

算力成本往往是AI产品成本中最大的一块。你需要做一个粗略的成本估算：

推理成本估算公式：

月度推理成本 ≈ 日均调用次数 × 单次调用平均Token数 × Token单价 × 30天

举例：
- 日均调用：10,000次
- 单次平均Token：2,000（输入1,500 + 输出500）
- Token单价：￥0.005 / 1K tokens（GPT-4级别模型）
- 月度成本 = 10,000 × 2,000 × 0.005 / 1,000 × 30 = ￥3,000/月

成本优化策略

  • 模型路由（Model Routing）：简单请求走小模型，复杂请求走大模型
  • 缓存策略：对重复问题缓存答案
  • 量化与蒸馏：用大模型生成数据，训练小模型
  • Prompt优化：通过更好的Prompt减少输出Token长度

# 2.3 商业可行性维度：能不能赚钱？

技术可行不等于商业可行。一个AI需求最终能不能落地，还要看商业模式是否成立。

# 2.3.1 市场规模（TAM/SAM/SOM）

指标全称含义计算方法
TAMTotal Addressable Market总可触达市场所有可能用该产品的用户 × ARPU
SAMServiceable Addressable Market可服务市场你能触达的市场细分
SOMServiceable Obtainable Market可获得市场短期内实际能获得的市场份额

举例：AI智能客服

  • TAM：全国所有需要客服的企业 = 数百万家企业 × 年费万元级 = 千亿级市场
  • SAM：你聚焦的电商行业中小企业 = 数十万家 × 年费5千 = 数十亿级
  • SOM：第一年你能触达并转化的客户 = 500家 × 年费5千 = 250万

# 2.3.2 竞争格局分析

竞争维度评估内容竞争策略
直接竞品有没有成熟的同类产品？差异化定位或正面竞争
间接替代用户现在用什么方式解决？（人工、传统软件）证明AI方案10倍优于替代方案
技术壁垒你的技术护城河是什么？数据飞轮、独家算法、行业Know-how
巨头威胁BAT/字节/微软会不会跟进？深耕垂直场景，巨头不愿意做的"脏活累活"

# 2.3.3 变现路径

变现模式适用场景优势挑战
SaaS订阅企业级AI工具收入稳定、可预测获客成本高、销售周期长
按量付费API服务灵活、用户门槛低收入波动大
效果付费广告、推荐ROI明确效果衡量复杂
增值功能C端产品加AI功能用户基数大付费转化率低
数据服务提供AI标注/训练数据技术门槛相对较低规模化难

# 2.3.4 投入产出比（ROI）

做一个粗略的ROI估算：

ROI = (预期年收入 - 年度总成本) / 年度总成本 × 100%

年度总成本 = 人力成本 + 算力成本 + 数据成本 + 运营成本

举例：
- 人力成本：5人 × 30万/年 = 150万
- 算力成本：30万/年
- 数据成本：20万/年
- 运营成本：20万/年
- 年度总成本 = 220万
- 预期年收入（第2年）= 400万
- ROI = (400-220)/220 = 82%

ROI评估陷阱

  • 低估成本：很多团队只算"开发成本"，不算"模型持续迭代成本"
  • 高估收入："如果我们拿下1%的市场..."——1%的市场往往比你想象的大得多，也难得多
  • 忽略时间价值：AI项目的回报周期通常比传统产品更长

# 2.4 风险可控维度：最坏的情况是什么？

AI产品面临的风险维度比传统产品更多。你需要一个系统性的风险评估框架。

# 2.4.1 幻觉风险（Hallucination Risk）

大模型会"一本正经地胡说八道"，这在某些场景下可能造成严重后果。

风险等级场景应对策略
🔴 极高AI医疗诊断、AI法律咨询、AI金融建议必须人工审核，不能作为唯一依据
🟡 中高AI新闻写作、AI教育辅导事实核查机制，置信度低时提醒用户
🟢 低AI创意写作、AI聊天陪伴明确告知用户"内容由AI生成"

# 2.4.2 合规风险

合规领域核心要求违规后果
算法备案中国境内深度合成服务需备案下架、罚款
数据安全个人信息保护法、GDPR巨额罚款、品牌受损
内容安全AI生成内容需标识、不能生成违禁内容下架、法律责任
行业监管金融、医疗、教育等行业的特殊要求牌照吊销、刑事责任

# 2.4.3 伦理风险

  • 算法偏见：招聘AI对某类人群歧视
  • 深度伪造：AI换脸、语音克隆被用于诈骗
  • 版权争议：AI训练数据是否侵犯版权
  • 就业冲击：AI替代人工带来的社会问题

# 2.4.4 品牌风险

如果AI功能表现不佳，可能伤害整体品牌形象。

品牌风险案例

品牌风险案例

某知名互联网公司推出AI搜索功能，因为幻觉问题严重，给用户推荐了错误信息，引发舆论危机。最后该功能被紧急下线，公司股价下跌，品牌受损。

教训：AI功能上线前，必须做充分的压力测试和边界测试。宁可不上，也不要上一个"半成品"。

# 3.2 RICE模型在AI场景的改良版

RICE是经典的优先级排序模型：

RICE Score = (Reach × Impact × Confidence) / Effort
1

但在AI场景下，我们需要做一些改良：

原版RICEAI改良版改良说明
Reach（触达人数）Reach × 使用频次AI产品频次差异大，高频需求应加权
Impact（影响力）Impact × 模型效果置信度模型效果不确定，需打折
Confidence（信心度）Confidence × 数据就绪度数据质量影响交付信心
Effort（工作量）Effort + 模型迭代成本传统工作量+数据准备+模型调优

改良版公式：

AI-RICE = (Reach × Freq × Impact × ModelConfidence × DataReadiness) / (DevEffort + DataEffort + ModelIterCost)
1

象限特征策略举例

核心考点

关键洞察

AI领域有很多"第四象限"机会——即用现成的API实现高价值功能。比如接入GPT-4做智能客服问答、用Whisper做语音转写。这些需求的共同特点是：不需要自研模型，调用现成API即可，成本可控，效果有基础保障。

建议团队定期梳理这类"快速Win"需求，快速上线验证。

# 五、实战案例

# 案例一：评估"AI自动生成会议纪要"需求

# 背景

某SaaS协同办公产品的产品经理小王，收到了很多用户反馈："能不能加一个功能，开会后自动出会议纪要？"小王觉得这个需求很有价值，准备做一个评估。

# 用户价值维度评估

评估项分析评分
需求真实性用户反馈频繁（月均50+条），竞品（飞书、钉钉）已有类似功能⭐⭐⭐⭐⭐
需求频次职场人群每周3-5次会议，高频⭐⭐⭐⭐⭐
痛点强度人工整理纪要耗时30-60分钟/场，且容易遗漏重点⭐⭐⭐⭐
付费意愿调研显示67%的用户愿意为该功能付费10-30元/月⭐⭐⭐⭐

# 技术可行性维度评估

评估项分析评分
模型能力当前ASR（语音识别）+LLM（文本总结）技术已非常成熟。Whisper语音识别准确率>95%，GPT-4总结质量接近人工⭐⭐⭐⭐⭐
数据可用性需要会议纪要数据集。公开数据集（如AMI Meeting Corpus）可用，但领域差异大。需要收集内部会议数据（需脱敏）⭐⭐⭐
团队能力团队有NLP经验，做过文本摘要功能⭐⭐⭐⭐
算力成本会议录音平均1小时=约10MB，ASR+LLM处理一次约￥0.5。月活1万用户，每周3次会议 = ￥6万/月⭐⭐⭐

# 商业可行性维度评估

评估项分析评分
市场规模协同办公市场千亿级，会议纪要作为增值功能，TAM约10亿⭐⭐⭐⭐
竞争格局飞书、钉钉已有基础版，但质量一般。差异化空间在于"行业模板"和"Action Item提取"⭐⭐⭐⭐
变现路径作为高级版功能，20元/人/月⭐⭐⭐⭐
ROI预估开发成本约100万，年运营成本150万。预计年收入500万。ROI = (500-250)/250 = 100%⭐⭐⭐⭐

# 风险可控维度评估

评估项分析评分
幻觉风险会议纪要总结可能遗漏重点或误解语义。但风险可控——不涉及医疗/法律等高风险领域⭐⭐⭐⭐
合规风险会议录音涉及隐私，需用户明确授权。需符合《个人信息保护法》⭐⭐⭐
伦理风险较低。但需考虑"未经同意录音"的伦理问题⭐⭐⭐⭐
品牌风险如果纪要质量差，会影响产品口碑。需设置质量阈值，不达标时提示用户"AI总结，建议复核"⭐⭐⭐

# 效果-成本矩阵定位

  • 预期效果：高（技术成熟，用户痛点明确）
  • 实现成本：中（调用现成API+业务层开发，无需自研模型）
  • 定位：第四象限偏中间 → 快速Wins，应优先投入

# 综合评分卡

维度加权得分说明
用户价值4.5/5需求真实、高频、痛点强
技术可行性4.0/5技术成熟，但数据需准备
商业可行性4.0/5市场大，变现路径清晰
风险可控3.5/5隐私合规需重视
总分4.0/5优质需求，建议尽快启动

# 决策结论

启动开发，但需注意以下事项：

  1. 优先调用现成API（Whisper+GPT-4），不要做自研模型
  2. 数据隐私要做合规审查，录音需用户明确授权
  3. 上线时设置"AI生成，建议复核"的提示
  4. 做好效果监控：用户编辑率、用户满意度

# 案例二：评估"AI医疗诊断助手"需求

# 背景

某互联网医疗公司的产品经理小李，接到老板的指示："现在AI这么火，我们能不能做一个AI医生，帮用户在线诊断？"小李觉得这个需求需要慎重评估。

# 用户价值维度评估

评估项分析评分
需求真实性用户确实有"小病不想去医院"的痛点，线上问诊需求真实⭐⭐⭐⭐
需求频次健康人群低频（年均几次），慢性病患者中频（每月）⭐⭐⭐
痛点强度对急症患者是致命痛点，但对普通用户是轻微不便⭐⭐⭐
付费意愿调研显示用户更信任真人医生，对AI诊断付费意愿低（<20%）⭐⭐

# 技术可行性维度评估

评估项分析评分
模型能力当前大模型在医学知识上有一定能力，但诊断准确率远未达到临床标准。GPT-4在美国医师资格考试(USMLE)上表现接近及格线，但实际临床诊断涉及查体、化验、影像，远超纯文本问答⭐⭐
数据可用性需要大量真实病例数据。但医疗数据受严格保护（HIPAA、等保），获取难度极高⭐⭐
团队能力团队主要是互联网背景，缺乏医学专家和临床AI经验⭐⭐
算力成本需要高质量模型+医学知识库，推理成本高。且需要通过NMPA审批，需要大量临床验证⭐⭐

# 商业可行性维度评估

评估项分析评分
市场规模互联网医疗市场千亿级，但AI诊断是其中的小众场景⭐⭐⭐
竞争格局阿里健康、京东健康、微医等巨头在做，且都在真人问诊+AI辅助的混合模式⭐⭐⭐
变现路径用户付费意愿低，主要靠B端（医院、体检机构）采购⭐⭐⭐
ROI预估研发成本极高（需临床验证、审批），回报周期长（3-5年），短期难以盈利⭐⭐

# 风险可控维度评估

评估项分析评分
幻觉风险极高。误诊可能导致用户延误治疗，造成人身伤害⭐
合规风险极高。医疗AI需要通过NMPA三类医疗器械审批，流程2-3年，且需要临床试验⭐
伦理风险高。AI替代医生诊断涉及生命伦理问题⭐⭐
品牌风险极高。一旦误诊导致事故，品牌将遭受毁灭性打击⭐

# 效果-成本矩阵定位

  • 预期效果：中低（当前技术难以达到临床可用水平）
  • 实现成本：极高（研发+临床+审批）
  • 定位：第二象限 → 战略投入区，但风险极高

# 综合评分卡

维度加权得分说明
用户价值2.5/5需求真实，但付费意愿低
技术可行性2.0/5技术不成熟，团队缺乏医学背景
商业可行性2.5/5市场大但变现难，ROI差
风险可控1.0/5风险极高，涉及生命安全
总分2.0/5高风险需求，建议放弃或大幅调整范围

# 决策结论

不建议以"AI医生"的形式直接启动。建议调整方案为：

  1. 降级为"AI预问诊助手"：不给出诊断结论，只收集症状信息、提供健康科普、建议就医科室。将风险从"诊断"降到"分诊"。
  2. B端优先：先卖给医院/体检机构做"智能导诊"，不直接面向C端用户。
  3. 与真人医生结合：AI辅助医生，而非替代医生。医生做最终诊断，AI做信息整理和知识检索。
  4. 长期布局：如果公司战略坚定要做，可以成立独立的医学AI团队，从科研合作开始，走临床验证+审批的长线。

关键教训

关键教训

AI医疗是典型的"高价值+高风险"场景。做这类产品的黄金法则是：先合规，再产品；先辅助，再替代；先B端，再C端。

任何涉及生命安全的AI产品，都不能用互联网"快速试错"的思路来做。

# 六、常见误区

# 误区一：低估数据准备成本

典型表现：

"我们有用户行为日志，直接拿来做训练数据不就行了？"

现实：

  • 原始日志≠标注数据。从原始数据到训练数据，中间隔着清洗、标注、质检等多个环节。
  • 一个AI项目，数据准备往往占**50%-70%**的总工作量。

应对：

  • 评估阶段就要求算法团队做数据探查
  • 预留充足的数据预算和时间
  • 考虑使用公开数据集+少量业务数据做冷启动

# 误区二：高估模型效果

典型表现：

"GPT-4那么强，做这个功能肯定没问题"

现实：

  • 通用模型在特定垂直场景的效果往往不如预期
  • 模型的"演示效果"和"生产效果"差距巨大
  • 真实业务数据的噪声、分布偏移会让效果大打折扣

应对：

  • 用真实业务数据做PoC，不要拿Demo数据测试
  • 设置合理的预期：首次上线能达到SOTA的70%就算成功
  • 预留模型迭代时间和预算

# 误区三：忽视维护成本

典型表现：

"模型训练好了，上线就完事了"

现实：

  • AI模型需要持续监控：效果衰减、数据漂移、用户投诉
  • 模型需要定期迭代：业务变化、新数据积累、新模型发布
  • 基础设施需要持续维护：GPU集群、推理服务、监控告警

应对：

  • 在ROI计算中加入年度维护成本（通常占开发成本的30%-50%）
  • 建立模型效果监控体系
  • 制定模型迭代计划（建议每季度至少评估一次是否需要迭代）

# 误区四：忽视兜底策略

典型表现：

"模型效果不好的时候，用户将就一下呗"

现实：

  • AI产品必须有完善的兜底策略（Fallback Strategy）
  • 模型失效时用户体验不能断崖式下跌

应对：

  • 设计降级方案：模型置信度低时，转人工或给出提示
  • 设置熔断机制：模型异常时自动切换备用方案
  • 准备友好的错误提示：不要让用户看到"模型错误"这种技术语言

# 误区五：为了AI而AI

典型表现：

"现在AI是风口，我们产品不加个AI功能就落后了"

现实：

  • 很多功能用规则引擎就能实现，没必要上AI
  • AI的引入会增加复杂度和不确定性

应对：

  • 评估前先问：这个功能用传统方法能不能做？
  • 如果传统方法能达到90分，AI只能达到95分，但成本翻倍——那就用传统方法
  • AI应该用来解决"传统方法解决不了"或"解决得不好"的问题

# 七、写在最后

恭喜你读完了这一节！我们系统性地聊了AI需求评估的四维框架、四套实用工具、完整的评估流程，还拆解了两个完整的实战案例。

记住，AI需求评估的核心不是"能不能做"，而是"值不值得做、能不能做好、最坏的情况是什么"。当你拿到一个新的AI需求时，希望你能够：

  1. 先问用户价值：用户真的需要吗？愿意付费吗？
  2. 再问技术可行性：现有模型能做到什么程度？数据够吗？成本可控吗？
  3. 三问商业可行性：市场多大？怎么赚钱？ROI算得过来吗？
  4. 最后问风险：幻觉怎么办？合规吗？品牌能承受失败吗？

如果你能把这四个维度都想清楚，你就已经超过80%的AI产品经理了。
